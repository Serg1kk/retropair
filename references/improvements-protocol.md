# Протокол предложений движку

Правило для скиллов `setup`, `collect`, `review` и `report`: как записать предложение по улучшению
самого плагина, когда работа упёрлась в его ограничение. Предложения лежат в
`.sessionretro/improvements/` проекта пользователя и никуда не уходят сами: отправляет только
пользователь, своей командой.

Все команды — через CLI плагина:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" improve <действие> …
```

Если литерал `${CLAUDE_PLUGIN_ROOT}` не подставился — корень плагина на два уровня выше папки
`scripts/lib/` (там лежит `.claude-plugin/plugin.json`).

## Когда предлагать

Только когда мешает **плагин**, а не вкус пользователя:

- нужной возможности нет (команда не умеет, формат не читается, шаблон не покрывает случай);
- воспроизводимый сбой скрипта или скилла;
- пришлось обходить плагин руками, чтобы довести работу до конца.

Не предлагать:

- по пожеланиям к тону, длине и стилю текста — это настройки карточки человека и шаблона;
- по ошибкам данных пользователя (битый конфиг, нет логов) — это сообщение об ошибке, не предложение;
- в прогонах с `--no-ask` и в любых неинтерактивных прогонах (хук, `claude -p`, фоновый сбор):
  там некому ответить, предложение не задаётся и не записывается;
- повторно в той же сессии, если пользователь ответил «нет».

## Порядок

1. **Сначала обход.** Доведите текущую задачу до результата локальным обходом; предложение не
   заменяет работу.
2. **Дедуп.** Посмотрите, нет ли уже такого предложения:

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" improve list
   ```

   Тот же компонент и тот же симптом в `pending` или `sent` — новое не пишется; скажите
   пользователю, что предложение уже записано, и назовите его ID.
3. **Одна реплика.** Одним сообщением: что упёрлось, как обошли, что предлагаете, и вопрос
   «Записать предложение для авторов плагина?». Без уговоров и без повторов.
4. **Запись только по согласию** («да», «ок», «запиши»):

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" improve add \
     --component "<скилл или часть движка>" \
     --symptom "<что не вышло и в какой ситуации — обезличенно>" \
     --workaround "<как обошли в этот раз>" \
     --proposal "причина — …; подход — …; критерий успеха — …"
   ```

   Необязательный `--slug <латиница-через-дефис>` задаёт слаг ID; по умолчанию он берётся из
   компонента. Команда печатает путь к файлу `imp-ГГГГММДД-<слаг>-<hex4>.md`.

Отказ команды с кодом 1 значит, что после обезличивания в тексте остались путь с логином, e-mail
или имя человека из карточек. Перепишите поле без них и повторите; обходить проверку нельзя.

## Что не писать и не слать

- содержимое логов и цитаты из сессий;
- имена, хэндлы, e-mail людей проекта, названия компании и проекта пользователя;
- пути машины с логином, ключи, токены, адреса внутренних сервисов;
- оценки и тексты ревью.

Пишите симптом так, чтобы он был понятен без проекта: «пачка из 200 ходов не влезла в лимит
судьи», а не пересказ конкретной сессии. Команда `improve add` дополнительно прогоняет текст через
санитайзер плагина (имена из карточек → `[NAME]`, e-mail → `[EMAIL]`, домашние пути → `~`), но
это страховка, а не повод писать личное.

## Пакет — только по просьбе

Пакет собирается, только когда пользователь сам попросил отправить предложения («отправь
предложения», «собери пакет для авторов»). Не предлагайте его по своей инициативе.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" improve pack
```

Команда собирает все `pending` в один файл `improvements/pack-ГГГГММДД-<hex4>.md`, ещё раз
проверяет его на пути, e-mail и имена из карточек, печатает пакет целиком и строку
`gh issue create --repo … --label proposal --title … --body-file …`. Сама она ничего не
отправляет и `gh` не запускает.

Дальше:

1. Покажите пользователю пакет целиком — ровно то, что уйдёт, и попросите перечитать его на
   личные данные.
2. Отправляет пользователь сам: запускает напечатанную команду `gh` или вставляет текст пакета в
   issue репозитория плагина вручную. Агент эту команду не запускает.
3. После отправки отметьте предложения:

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" improve sent <ID> …
   ```

## Статусы

| Статус | Что значит | Кто ставит |
|---|---|---|
| `pending` | записано, не отправлено | `improve add` |
| `sent` | пользователь отправил пакет | `improve sent <ID>…` |
| `implemented (X.Y.Z)` | внедрено в версии X.Y.Z, файл перенесён в `improvements/archive/` | `improve sync` |

`improve sync` читает CHANGELOG плагина (или файл из `--changelog`): строка `внедрено: <ID>` под
заголовком версии `## [X.Y.Z]` переводит предложение в `implemented (X.Y.Z)`. Упоминание ID без
`внедрено:` и строки под `[Unreleased]` не в счёт. Архив дальше не читается: `improve list` и
дедуп его не видят. Число `pending` показывает `doctor` в строке `improvements_pending`.
