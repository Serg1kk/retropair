# OpenCode

Честно с самого начала: эта связка не прогонялась, и SpecStory OpenCode не поддерживает.
Зато OpenCode хранит историю локально, поэтому путь ручной: найти, сохранить в markdown,
собрать.

Одна оговорка: служебные файлы истории OpenCode sessionretro 0.1 не разбирает. Переписку
надо сохранить в markdown — экспортом самого OpenCode, если он есть в вашей версии,
или вручную.

## Шаг 1. Найдите, где лежат ваши сессии

```bash
ls -lt ~/.local/share/opencode/ 2>/dev/null
find ~ -maxdepth 5 -type d -iname "*opencode*" 2>/dev/null | grep -v Trash | head
```

Ищите внутри папку с сессиями или историей, обычно это `storage`, `sessions` или `history`.
Сделайте это **до начала работы**: если у вашей сборки всё иначе, лучше узнать заранее.

## Шаг 2. Проверьте, что история пишется

Поработайте с агентом пять минут в папке проекта и повторите команды из первого шага,
глядя на время изменения файлов. Свежая метка времени означает, что история пишется.

## Шаг 3. Заведите папку для логов и подключите её

```bash
cd путь/к/проекту
mkdir -p ai-logs
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" init --mode self
```

Последняя команда нужна один раз, если workspace ещё нет. В `.sessionretro/config.json`
в поле `sources` добавьте папку:

```json
"sources": [
  {"type": "dir", "path": "ai-logs"}
]
```

## Шаг 4. Сохраните нужные сессии

Для каждой сессии по этому проекту сохраните переписку в `ai-logs/` — одна сессия, один
файл, например `ai-logs/session-2026-01-15.md`. Роли размечайте заголовками, а дату —
строкой `Date:`:

```markdown
Date: 2026-01-15

## User
текст запроса

## Assistant
ответ агента
```

Сохраняйте только те сессии, что относятся к этому проекту. В общем каталоге лежит
и другая рабочая переписка, она уезжать никуда не должна.

## Шаг 5. Соберите и вычистите

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

Этот шаг обязательный: при ручном сохранении никакой встроенной вычистки нет. Команда
копирует каждый файл снимком в `.sessionretro/logs/me/` и по дороге вычищает его
встроенным санитайзером. Файлы в `ai-logs/` не меняются, `*.orig` плагин не пишет.

Имена собственные регулярным выражением не ловятся. Впишите свои названия и фамилии
в `.sessionretro/config.json`:

```json
"sanitize": {"names": ["ООО Ромашка", "Иванов"], "extra_patterns": []}
```

Затем посмотрите глазами:

```bash
grep -rn "REDACTED\|SECRET_ASSIGNMENT\|API_KEY\|EMAIL\|PHONE\|NAME" .sessionretro/logs | head
```

В лог попадает содержимое файлов, которые агент читал, то есть ваш код.

## Если логи смотрит другой человек

Ревьюер собирает логи из вашего приватного репозитория. Отдавайте уже вычищенные снимки,
а не сырую папку `ai-logs`:

```bash
git add .sessionretro/logs
git commit -m "логи сессий"
git push origin
```

## Если что-то не сходится

Инструкция собрана по общему принципу, а не по прогону. Откройте issue в репозитории
плагина и приложите вывод команд из первого шага — инструкцию поправят.

В сводке `collect` у файла ноль ходов. Проверьте разметку ролей: заголовки `## User`
и `## Assistant` на отдельных строках.
