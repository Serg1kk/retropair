# crush

Честно с самого начала: эта связка не прогонялась, и ни один проверенный сборщик crush
не поддерживает. Зато crush хранит историю сессий локально, и этого достаточно для
ручного пути.

## Шаг 1. Найдите, где лежат ваши сессии

Сделайте это **до начала работы**, а не после.

```bash
ls -lt ~/.local/share/crush/ 2>/dev/null
ls -lt ~/.config/crush/ 2>/dev/null
find ~ -maxdepth 5 -type d -iname "*crush*" 2>/dev/null | grep -v Trash | head
```

Ищите внутри базу или папку с сессиями: у crush история обычно лежит одним файлом базы
данных на всё либо папкой с сессиями по проектам. Если внутри проекта есть локальная
папка `.crush`, посмотрите и в ней:

```bash
ls -la путь/к/проекту/.crush 2>/dev/null
```

## Шаг 2. Проверьте, что история вообще пишется

Поработайте с агентом пять минут в папке проекта и повторите команды из первого шага,
глядя на время изменения файлов. Свежая метка времени означает, что история пишется.

## Шаг 3. Заведите папку для логов и подключите её

```bash
cd путь/к/проекту
mkdir -p ai-logs
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" init --mode self
```

Последняя команда нужна один раз, если workspace ещё нет. В `.retropair/config.json`
в поле `sources` добавьте папку:

```json
"sources": [
  {"type": "dir", "path": "ai-logs"}
]
```

## Шаг 4. Сохраните нужные сессии

Базу crush целиком не копируйте: общая база на все проекты в репозитории оказаться
не должна, и RetroPair её всё равно не разберёт. Выгрузите нужную сессию через
интерфейс самого crush, если он это умеет, либо скопируйте переписку вручную в файл
`ai-logs/session-2026-01-15.md`. Роли размечайте заголовками, а дату — строкой `Date:`:

```markdown
Date: 2026-01-15

## User
текст запроса

## Assistant
ответ агента
```

Сохраняйте только то, что относится к этому проекту: другая рабочая переписка
уезжать никуда не должна.

## Шаг 5. Соберите и вычистите

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" collect
```

Обязательно, встроенной вычистки здесь нет. Команда копирует каждый файл снимком
в `.retropair/logs/me/` и по дороге вычищает его встроенным санитайзером. Файлы
в `ai-logs/` не меняются, `*.orig` плагин не пишет.

Имена собственные регулярным выражением не ловятся. Впишите свои названия, фамилии
и внутренние системы в `.retropair/config.json`:

```json
"sanitize": {"names": ["ООО Ромашка", "Иванов"], "extra_patterns": []}
```

Затем откройте один снимок и пролистайте глазами:

```bash
grep -rn "REDACTED\|SECRET_ASSIGNMENT\|API_KEY\|EMAIL\|PHONE\|NAME" .retropair/logs | head
```

В историю попадает содержимое файлов, которые агент читал, то есть ваш код.

## Если логи смотрит другой человек

Ревьюер собирает логи из вашего приватного репозитория. Отдавайте уже вычищенные снимки,
а не сырую папку `ai-logs`:

```bash
git add .retropair/logs
git commit -m "логи сессий"
git push origin
```

## Если что-то не сходится

Инструкция собрана по общему принципу, а не по прогону. Откройте issue в репозитории
плагина и приложите вывод команд из первого шага — инструкцию поправят.

В сводке `collect` у файла ноль ходов. Проверьте разметку ролей: заголовки `## User`
и `## Assistant` на отдельных строках.
