# VS Code плюс Claude Code

Путь проверен целиком на настоящих файлах сессий Claude Code, включая редакцию
на подложенных секретах. Отдельный вопрос, пишет ли расширение VS Code на диск вообще,
закрыт: пишет.

Ставить ничего, кроме sessionretro, не нужно: плагин читает сессии Claude Code напрямую.
SpecStory — по желанию, если нужна ещё и markdown-копия (раздел в конце).

## Куда пишутся ваши логи

Документация вендора про это противоречит сама себе: одна страница говорит, что расширение
и терминальный CLI делят одну историю, другая говорит, что у панели своя. Внутри
расширения лежит тот же самый бинарь CLI той же версии, расширение просто запускает его.
Значит, история одна, и сессии из панели ложатся туда же, куда из терминала:
`~/.claude/projects/<путь-проекта>/`, одним файлом `.jsonl` на сессию.

## Шаг 1. Проверьте до начала работы

Откройте терминал внутри VS Code, зайдите в папку проекта и выполните:

```bash
ls -lt ~/.claude/projects/$(pwd | sed 's/[^A-Za-z0-9]/-/g')/*.jsonl | head -3
```

Должен получиться список файлов, самый свежий сверху. Если проект новый, поработайте
с агентом пять минут и повторите. Пусто после реальной работы — значит, у вас что-то
нестандартное, см. раздел «Если что-то не сходится».

Форма команды важна: она заменяет на дефис каждый символ, кроме букв и цифр, а не только
слэши. Более простые варианты на путях с пробелами показывают пустоту, хотя сессии есть.

## Шаг 2. Подключите источник

Один раз в корне проекта создайте workspace, если его ещё нет:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" init --mode self
```

В `.sessionretro/config.json` в поле `sources` добавьте источник Claude Code:

```json
"sources": [
  {"type": "claude-jsonl", "project": "auto"}
]
```

`auto` — сессии этого проекта. Остальные ваши сессии, включая рабочие, плагин не тронет.

## Шаг 3. Соберите и вычистите

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

Команда копирует каждую сессию снимком в `.sessionretro/logs/me/` и по дороге вычищает его
встроенным санитайзером: секреты, пароли, почту, телефоны, строки подключения, имя
пользователя ОС в путях. Исходные файлы сессий не меняются, `*.orig` плагин не пишет.
В конце — сводка: сколько сессий новых, выросших, без изменений и что где заменено.

Имена собственные регулярным выражением не ловятся. Впишите свои названия и фамилии —
компанию, коллег, внутренние системы — в `.sessionretro/config.json`:

```json
"sanitize": {"names": ["ООО Ромашка", "Иванов"], "extra_patterns": []}
```

Учтите срок: Claude Code сам удаляет свои транскрипты примерно через тридцать дней.
Снимок в `.sessionretro/logs/` остаётся, но собрать надо успеть. Проще всего включить
автосбор в конце каждой сессии Claude Code — в `.sessionretro/config.json`:

```json
"hook": {"enabled": true, "providers": ["claude"]}
```

## Шаг 4. Посмотрите своими глазами

```bash
grep -rn "REDACTED\|SECRET_ASSIGNMENT\|API_KEY\|EMAIL\|PHONE\|NAME" .sessionretro/logs | head
```

Затем откройте один снимок целиком и пролистайте: автоматика ловит форматы, а название
клиента в свободном тексте видите только вы. В лог попадает содержимое файлов, которые
агент читал, то есть ваш код.

Самопроверка перед первым использованием: положите в промпт агенту заведомую строку
`TEST_EMAIL = "a@example.com"`, выполните шаг 3 и убедитесь, что в снимке на её месте
стоит `[EMAIL]`, а в сводке у этого файла есть срабатывание `email`.

## Если логи смотрит другой человек

Ревьюер собирает логи из вашего приватного репозитория. Отдавайте уже вычищенные снимки,
а не сырые сессии:

```bash
git add .sessionretro/logs
git commit -m "логи сессий"
git push origin
```

Если после отправки поработаете с агентом ещё, повторите шаги 3, 4 и отправку:
`collect` допишет новые и выросшие сессии, неизменные снимки не тронет.

## По желанию: markdown-копия через SpecStory

SpecStory разворачивает сессии в обычные markdown-файлы в `.specstory/history/` —
удобно читать глазами. Для sessionretro это второй источник той же сессии: при дубле
побеждает `claude-jsonl`, в нём больше данных.

Установка:

```bash
brew tap specstoryai/tap
brew install specstory
specstory version
```

Если `brew install` ругается на Command Line Tools, возьмите готовый бинарь:

```bash
curl -fsSL -o specstory.tar.gz \
  https://github.com/specstoryai/getspecstory/releases/download/v2.6.0/SpecStoryCLI_Darwin_arm64.tar.gz
tar -xzf specstory.tar.gz && chmod +x specstory
mkdir -p ~/.local/bin && mv specstory ~/.local/bin/
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
export PATH="$HOME/.local/bin:$PATH"
specstory version
```

Для Intel замените `arm64` на `x86_64`, для Linux возьмите `SpecStoryCLI_Linux_arm64.tar.gz`
или `SpecStoryCLI_Linux_x86_64.tar.gz` из того же релиза. Архив `specstory.tar.gz`
после распаковки можно удалить. Под Windows SpecStory нет — см. [windows.md](windows.md).

Сразу после установки отключите сеть инструмента (тот же конфиг лежит рядом:
[specstory-config.toml](specstory-config.toml)):

```bash
mkdir -p ~/.specstory/cli
cat > ~/.specstory/cli/config.toml <<'EOF'
# SpecStory без сети. В аккаунт не входить, specstory login не запускать.

[cloud_sync]
enabled = false

[analytics]
enabled = false

[version_check]
enabled = false

[telemetry]
prompts = false

[redaction]
enabled = true
EOF
```

По умолчанию SpecStory при каждом запуске проверяет обновления и отправляет анонимную
аналитику, а при входе в аккаунт синхронизирует сессии в своё облако. Конфиг выключает
всё это разом. В аккаунт не входите и `specstory login` не запускайте.

Добавьте источник рядом с `claude-jsonl`:

```json
{"type": "specstory", "path": ".specstory/history"}
```

Теперь `collect` сам запускает `specstory sync claude` перед сбором. Сырые файлы
в `.specstory/history/` не вычищены и носят в имени кусок первого промпта — в общий
репозиторий их не кладите.

## Если что-то не сходится

Проверка из первого шага пуста, хотя вы работали в панели. Откройте встроенный терминал
VS Code, запустите агента командой `claude` оттуда и повторите проверку. Если и так пусто,
откройте issue в репозитории плагина и приложите вывод команды.

В сводке `collect` предупреждение «папки нет, источник пропущен». Проверьте, что запускаете
команду в корне того же проекта, в котором работали с агентом.

`specstory sync claude` говорит, что сессий нет. Проверьте, что вы в папке того же
репозитория, в котором работали с агентом.
