# Логи работы с агентом: найдите свою связку

По готовому коду не видно, как ставилась задача, где агента остановили и что решили
проверить руками. По логу сессии видно. Здесь собраны инструкции, как получить логи
из вашей среды и вашего агента в виде, который sessionretro собирает сам.

Найдите в таблице свою связку и откройте её файл. В нём всё для этой связки: что проверить
до начала работы, что поставить, что настроить, как подключить источник к sessionretro
и как убедиться, что лишнее вычищено. Файлы не отсылают друг к другу, читать надо один.

Если пользуетесь двумя инструментами, берите файл того, в котором чаще пишете код с агентом.
Если своей связки не нашли, откройте issue в репозитории плагина.

## Как sessionretro собирает логи

Одна команда из корня проекта:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

Откуда брать логи, команда узнаёт из поля `sources` в `.sessionretro/config.json`
(workspace создаёт `sr.py init`). Типы источников:

| Тип | Что читает | Пример |
|---|---|---|
| `claude-jsonl` | сессии Claude Code из `~/.claude/projects/<проект>/` | `{"type": "claude-jsonl", "project": "auto"}` |
| `specstory` | markdown-выгрузки SpecStory; если SpecStory установлен, `collect` сам запускает `specstory sync` | `{"type": "specstory", "path": ".specstory/history"}` |
| `dir` | папка с `.md`, `.markdown`, `.txt`, `.jsonl` — для ручного экспорта | `{"type": "dir", "path": "ai-logs"}` |
| `git` | чужой репозиторий с логами, только режимы team и course | `{"type": "git", "url": "…"}` |

Какого агента выгружает `specstory sync`, задаёт `hook.providers` в конфиге (`claude`,
`codex`, `cursoride`, `antigravity`…) или флаг `--provider`; по умолчанию `claude`.

Что делает `collect`:

- копирует каждый лог снимком в `.sessionretro/logs/<id человека>/` и по дороге вычищает
  его встроенным санитайзером. Исходники не меняются, файлы `*.orig` плагин не пишет;
- называет снимок по ключу сессии, а не по имени выгрузки: в имени файла SpecStory лежит
  кусок первого промпта, и в `logs/` он не попадает;
- показывает сводку: сколько логов новых, выросших, без изменений, где и что санитайзер
  заменил, сколько найдено `*.orig` и файлов со слагом в имени;
- при повторе не переписывает неизменные снимки.

## ⚠️ Windows

SpecStory существует только под macOS и Linux, а сам `sr.py collect` на Windows в 0.1
не поддерживается: блокировка файлов, на которой держится сбор, там не работает.
Путь для Windows — ручной экспорт через `/export` и сбор на машине с macOS или Linux,
подробно в [windows.md](windows.md).

## Три вещи, которые важны для всех

Первое. Проверку из первого раздела своего файла сделайте **до того, как начнёте работу**,
а не после. Инструмент, который не нашёл сессий, и инструмент, который нашёл пустоту,
выглядят одинаково, а чинятся по-разному. Проверка занимает десять секунд.

Второе. В лог попадает не только переписка с агентом, но и содержимое файлов, которые агент
читал, то есть ваш код. Встроенная редакция SpecStory режет секреты известных форматов,
но не трогает почту, телефоны, фамилии, адреса, строки подключения к базе, пароли, похожие
на человеческие слова, и имя самого файла выгрузки. Это добивает санитайзер `collect`.
Имена собственные регулярным выражением не ловятся, поэтому свои названия — компанию,
коллег, внутренние системы — впишите в конфиг:

```json
"sanitize": {"names": ["ООО Ромашка", "Иванов"], "extra_patterns": []}
```

Имена из карточек людей (`name` в `.sessionretro/people/*.yaml`) санитайзер берёт сам,
`extra_patterns` — свои регулярные выражения, совпадения заменяются на `[REDACTED]`.

Третье. Автоматика ловит форматы, а название клиента в свободном тексте видите только вы.
Перед тем как отдавать логи кому-то, пролистайте хотя бы один снимок глазами.

## Если логи смотрит другой человек

В режимах team и course ревьюер собирает логи из вашего приватного репозитория источником
`git`. Санитайзер работает там, где запускают `collect`, поэтому надёжнее отдавать уже
вычищенные снимки: заведите у себя workspace (`sr.py init --mode self`), выполните
`collect` и передайте ревьюеру папку `.sessionretro/logs/<ваш id>/` — например, закоммитьте
в тот приватный репозиторий только её. Снимки в ней уже очищены, пути в `.meta.json` записаны
без логина. Перед этим пролистайте снимки глазами: название клиента в свободном тексте видите
только вы. Сырые `.specstory/history`, `ai-logs` и файлы `*.orig` в общий репозиторий
не кладите. Репозиторий должен быть приватным.

Если логи только для вас (режим self), `.sessionretro/logs/` не коммитьте вовсе.
