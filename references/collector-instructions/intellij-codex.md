# IntelliJ IDEA (или другой JetBrains) плюс Codex

Это единственная связка, где по умолчанию ничего не собирается. Прочитайте первый раздел
до конца, он короткий и решает всё.

Механика выгрузки и вычистки прогнана. Сама связка с JetBrains описана по официальной
базе знаний JetBrains и их трекеру задач: для живой проверки нужен вход в аккаунт внутри IDE.

Файлы сессий Codex sessionretro 0.1 напрямую не читает, поэтому понадобится SpecStory:
он разворачивает их в markdown, а `collect` собирает уже его.

## В чём особенность

Codex внутри JetBrains — не тот же Codex, что в терминале. Плагин держит **свои**
авторизацию, конфиг и сессии в отдельном служебном каталоге IDE, а не в общем `~/.codex`.
Переключить его штатной настройкой нельзя, такая возможность у вендора пока только
в запросах. Практическое следствие: SpecStory смотрит в общий каталог и ничего не найдёт,
хотя вы работали.

Лечится одним решением из двух, выберите любое.

**Первое, простое.** Запускайте `codex` из встроенного терминала IDE, а не из панели плагина.
Тогда он ведёт себя как обычный консольный Codex, пишет в общий каталог, и дальше всё
как у всех. Работать в IDE вы продолжаете как обычно, меняется только то, откуда
стартует агент. Рекомендуемый путь.

**Второе.** Оставить панель плагина, но запускать IDE с переменной окружения
`CODEX_HOME=~/.codex`, тогда плагин возьмёт общий каталог. Способ рабочий, но требует
запускать IDE особым образом, и это легко забыть.

## Шаг 1. Проверьте до начала работы

Посмотрите, где вообще лежат ваши сессии. Выполните обе команды, какая-то из них что-то покажет:

```bash
ls -lt ~/.codex/sessions/*/*/*/ | head -5
ls -d ~/Library/Caches/JetBrains/*/aia/codex/sessions 2>/dev/null
```

На Linux вторая команда выглядит так:

```bash
ls -d ~/.cache/JetBrains/*/aia/codex/sessions 2>/dev/null
```

Если файлы нашлись по первому пути, вы уже работаете через общий каталог, ничего менять
не надо. Если по первому пусто, а по второму каталог нашёлся, значит, вы работаете через
панель плагина, и надо применить одно из двух решений выше.

После того как применили, поработайте с агентом пять минут и повторите первую команду.
Файлы должны появиться. Не пропускайте эту проверку: она занимает минуту и отделяет
ситуацию «всё настроено» от ситуации «собралась пустота».

## Шаг 2. Поставьте SpecStory

Один раз.

```bash
brew tap specstoryai/tap
brew install specstory
specstory version
```

Если `brew install` ругается на Command Line Tools, возьмите готовый бинарь:

```bash
curl -fsSL -o specstory.tar.gz \
  https://github.com/specstoryai/getspecstory/releases/download/v2.6.0/SpecStoryCLI_Darwin_arm64.tar.gz
tar -xzf specstory.tar.gz && chmod +x specstory
mkdir -p ~/.local/bin && mv specstory ~/.local/bin/
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
export PATH="$HOME/.local/bin:$PATH"
specstory version
```

Последние строки кладут бинарь в постоянное место и добавляют его в PATH — после
этого `specstory` доступна из любого терминала, как при установке через brew.

Для Intel замените `arm64` на `x86_64`, для Linux возьмите Linux-архив из того же релиза.
Архив `specstory.tar.gz` после распаковки можно удалить. Под Windows SpecStory нет —
см. [windows.md](windows.md).

## Шаг 3. Отключите сеть инструмента

Тот же конфиг лежит рядом: [specstory-config.toml](specstory-config.toml).

```bash
mkdir -p ~/.specstory/cli
cat > ~/.specstory/cli/config.toml <<'EOF'
# SpecStory без сети. В аккаунт не входить, specstory login не запускать.

[cloud_sync]
enabled = false

[analytics]
enabled = false

[version_check]
enabled = false

[telemetry]
prompts = false

[redaction]
enabled = true
EOF
```

По умолчанию SpecStory проверяет обновления и отправляет анонимную аналитику, а при
входе в аккаунт синхронизирует сессии в облако. Конфиг выключает всё это разом.
В аккаунт не входите, `specstory login` не запускайте.

## Шаг 4. Подключите источник

Один раз в корне проекта создайте workspace, если его ещё нет:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" init --mode self
```

В `.sessionretro/config.json` добавьте источник SpecStory и укажите, какого агента
выгружать:

```json
"sources": [
  {"type": "specstory", "path": ".specstory/history"}
],
"hook": {"enabled": false, "providers": ["codex"]}
```

## Шаг 5. Соберите и вычистите

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

Команда сама запускает `specstory sync codex` в корне проекта, затем копирует каждую
выгрузку снимком в `.sessionretro/logs/me/` и по дороге вычищает его встроенным
санитайзером. Если в сводке у строки `specstory sync codex` «no sessions», вернитесь
к первому шагу: почти наверняка сессии всё ещё уходят в каталог плагина, а не в общий.

Встроенная редакция SpecStory (`[REDACTED:…]`) пропускает почту, телефоны, фамилии,
адреса, строки подключения и пароли, похожие на человеческие слова. И ещё: **имя файла**
выгрузки собирается из первого сообщения сессии до всякой редакции. Санитайзер `collect`
дочищает содержимое, а снимок называет по ключу сессии — кусок промпта из имени в `logs/`
не попадает. Исходные файлы не меняются, `*.orig` плагин не пишет.

Имена собственные регулярным выражением не ловятся. Впишите свои названия, фамилии
и внутренние системы в `.sessionretro/config.json`:

```json
"sanitize": {"names": ["ООО Ромашка", "Иванов"], "extra_patterns": []}
```

## Шаг 6. Посмотрите своими глазами

```bash
grep -rn "REDACTED\|SECRET_ASSIGNMENT\|API_KEY\|EMAIL\|PHONE\|NAME" .sessionretro/logs | head
```

Затем откройте один снимок и пролистайте. В лог попадает содержимое файлов, которые агент
читал, то есть ваш код.

Самопроверка перед первым использованием: положите в промпт агенту заведомую строку
`TEST_EMAIL = "a@example.com"`, выполните шаг 5 и убедитесь, что в снимке стоит `[EMAIL]`.

Честное ограничение Codex: в лог попадает переписка, но не каждый шаг агента.

## Если логи смотрит другой человек

Ревьюер собирает логи из вашего приватного репозитория. Отдавайте уже вычищенные снимки,
а не сырую выгрузку `.specstory/history`:

```bash
git add .sessionretro/logs
git commit -m "логи сессий"
git push origin
```

Если после отправки поработаете с агентом ещё, повторите шаги 5, 6 и отправку.

## Если что-то не сходится

Эту связку целиком прогнать не удалось. Если после первого шага не нашёлся ни один
из двух каталогов, или нашёлся второй, а после перехода на встроенный терминал сессии
всё равно не появляются, откройте issue в репозитории плагина и приложите вывод обеих
команд из первого шага — инструкцию поправят.

В сводке «specstory не найден, sync пропущен». SpecStory не в PATH того терминала, где
запускается `collect`: повторите шаг 2 и проверьте `specstory version`.
