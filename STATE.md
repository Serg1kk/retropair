# Состояние retropair

Код плагина обновляется, состояние пользователя — нет. Этот файл описывает, где живёт
состояние, кто его пишет и какие правила обязательны для любого кода плагина (скрипты, скиллы,
агенты, хук). Пользовательская версия того же — [docs/ru/workspace.md](docs/ru/workspace.md).

## Жёсткие правила

1. **Код пишет только в `.retropair/` проекта и в `~/.retropair/`.** Никогда внутрь
   папки плагина: при обновлении хост заменяет её целиком, и всё записанное туда пропадёт.
   Скиллы и агенты не хранят состояние в своих папках.
2. **Обновление плагина не трогает состояние.** Карточки, `_default.yaml`, `config.json`,
   свой шаблон текста, проектные агенты — это кастомизация пользователя. Новая версия читает
   их как есть; если формат меняется, нужна миграция (см. ниже), а не перезапись.
3. **Запись атомарная.** JSON пишется через временный файл в той же папке, `fsync` и
   `os.replace` (`write_json_atomic` в `scripts/lib/workspace.py`). Прерванная запись не
   оставляет полуфайла.
4. **Общие файлы — под блокировкой.** Реестр `~/.retropair/workspaces.json` меняется
   только под `file_lock` (`scripts/lib/lock.py`): `fcntl.flock` на соседний `<файл>.lock`,
   ожидание до 10 с, дальше ошибка с кодом 1. Lock-файл не удаляется. На Windows в 0.1
   блокировка не поддерживается — команда, которой она нужна, выходит с кодом 2.
5. **Запись только после проверки.** `config.json` валидируется схемой перед записью
   (`save_config`), новая карточка — после подстановки в шаблон и слияния с `_default.yaml`
   (`add_person`). Невалидное не пишется.
6. **Тихих фоллбеков нет.** Битый JSON, карточка не по схеме, id не совпадает с именем файла —
   ошибка `retropair: <что упало>: <почему> (<параметры>)` и код 1, а не «продолжим на
   дефолтах». Отсутствие файла там, где он обязателен, — код 2.

## Дерево и кто пишет

Workspace проекта:

```text
.retropair/
├── config.json               # init создаёт из templates/config.template.json; setup меняет; пользователь правит
├── people/_default.yaml      # init копирует из templates/_default.yaml; дальше только пользователь
├── people/<id>.yaml          # init (self: me.yaml) и people add из templates/person.template.yaml; пользователь правит
├── logs/<id>/…               # collect: очищенные копии логов
├── logs-index.json           # collect / inventory
├── runs/process-reviews.json # review: история оценок
├── runs/pending/*.json       # агенты сбора и оценки текущего прогона; можно удалять
├── reviews/<id>/…            # review пишет черновик, approve переводит в одобренное
├── reports/…                 # report; всегда пересобирается
├── templates/feedback.md     # пользователь (свой шаблон текста), плагин только читает
├── improvements/*.md         # скиллы с согласия пользователя: предложения по улучшению плагина
├── agents.json               # setup-apply / agents write: отпечатки тел проектных агентов
├── collect.log               # хук SessionEnd: вывод фоновых сборов, сам обрезается после 1 МБ
├── collect.lock              # collect: замок сбора (fcntl), не удаляется
└── plugin-state.json         # init; миграции
```

`agents.json` — `{"<роль>": {"sha256": "<хэш тела>", "plugin_version": "X.Y.Z"}}` по ролям
`collector`, `judge`, `critic`. Пишется при каждой записи файла агента в
`.claude/agents/retropair-*.md` (`scripts/lib/agents.py`). По нему `agents check` отличает
«файл не правили, обновилась болванка плагина» (файл обновляется сам) от «тело правлено вручную»
(файл не трогается). Нет записи — любое расхождение считается правкой человека. Файл можно
держать в git вместе с `.claude/agents/`.

Глобально:

```text
~/.retropair/
├── workspaces.json           # init регистрирует (scripts/lib/registry.py), под блокировкой
├── config.json               # setup: дефолты для новых workspace
├── reports/index.html        # report
├── clones/<ws>-<id>-<хэш>/   # collect: клоны git-источников логов (team, course)
└── plugin-state.json         # создаётся при первой регистрации workspace
```

Поиск workspace (`find_workspace`) идёт от текущей папки вверх до первой
`.retropair/config.json`; глобальная `~/.retropair/` workspace не считается, даже если
вы запускаете команду из домашнего каталога. `--workspace <папка>` задаёт проект явно.

## `plugin-state.json`

Служебная отметка хранилища, одна в каждом workspace и одна глобальная:

```json
{
  "formatVersion": 1,
  "pluginVersion": "0.1.0",
  "storeKind": "workspace",
  "migrations": [],
  "lastSync": null
}
```

| Поле | Смысл |
|---|---|
| `formatVersion` | версия формата хранилища; растёт только вместе с миграцией |
| `pluginVersion` | последняя версия плагина, работавшая с хранилищем (сдвигается любой командой `sr.py`, если плагин новее; битая или более новая отметка не меняется — строка предупреждения в stderr) |
| `storeKind` | `workspace` (папка проекта) или `global` (`~/.retropair/`) |
| `migrations` | id применённых миграций по порядку |
| `lastSync` | когда отметка последний раз сдвинулась на новую версию (UTC ISO 8601); `null` — не сдвигалась с создания |

В 0.1 миграций нет, формат 1. Когда формат впервые поменяется, миграция будет отдельным
файлом с планом (что изменится) и применением; отметка двигается только после успеха всей
цепочки, а изменённые файлы перед записью копируются в резервную папку.

## Схемы `config` и `person`

Схемы лежат в `references/schemas/config.json` и `references/schemas/person.json`, проверку
делает `scripts/lib/schema.py` (подмножество JSON Schema: `type`, `properties`, `required`,
`additionalProperties`, `items`, `enum`, `const`, `pattern`, `minLength`/`maxLength`,
`minimum`/`maximum`, `minItems`/`maxItems`).

- Схемы меняются **только добавлением необязательных полей**. Переименование, удаление,
  новое обязательное поле или сужение `enum` ломают существующие workspace — это смена
  `formatVersion` и миграция.
- На верхнем уровне `config.json` лишние ключи разрешены: расширение не требует правки схемы.
- `schema_version` в `config.json` — `1`.
- Схема карточки описывает **итоговую** карточку — после слияния с `people/_default.yaml`.
  Файл карточки может содержать только отличия от дефолтов.
- Карточки — YAML в узком подмножестве (`scripts/lib/yamlmini.py`): вложенные отображения,
  блочные списки «`- …`», строки, числа, `true`/`false`, `null`, комментарии; без
  flow-стиля (`[a, b]`, `{a: 1}`), якорей и многострочных `|`/`>`, отступы только пробелами.
  Экранирование внутри кавычек не
  разворачивается, поэтому имя с обеими кавычками или переводом строки не записывается
  (код 2).

## Что можно удалять

- `runs/pending/` и `reports/` — пересобираются.
- `logs/` — пересобирается повторным сбором, пока исходные логи агента не удалены
  (Claude Code чистит их по `cleanupPeriodDays`).
- Остальное — история и настройки пользователя; удалять только осознанно.

## Переход с SessionRetro

Новые каталоги `.retropair/` и `~/.retropair/` создаются только при отсутствии legacy state.
Существующий `.sessionretro/` переносится явной командой `rp.py migrate --apply`; сначала
выполните без `--apply` и остановите старый плагин. Два каталога блокируют операции.
Миграция не меняет JSON-ключи и исторические IDs; полный порядок — [инструкция](docs/ru/migration.md).
