# Мейнтейнерам retropair

Как принимаются решения, как выпускается релиз и какой файл владеет какой конвенцией. Для
контрибьютора — [CONTRIBUTING.md](CONTRIBUTING.md), для правил хранения данных —
[STATE.md](STATE.md), для тестов — [TESTING.md](TESTING.md).

## Роли

- **Владелец проекта** решает всё, что касается принципов оценки (ниже), состава осей и
  уровней, того, что видит адресат текста, и приватности. Изменение принципа — только
  явным решением владельца, с записью в CHANGELOG.
- **Мейнтейнеры** разбирают issues и PR, выпускают релизы, следят за гейтами и тестами.
- **Контрибьюторы** правят движок через PR: скрипты, скиллы, шаблоны, документацию,
  переводы. Правило одно — PR проходит тесты и гейты (см. [CONTRIBUTING.md](CONTRIBUTING.md)).
- **Изменения референсов осей и промптов оценщика** принимаются только через golden set:
  набор размеченных примеров, на котором прогоняется оценка до и после правки. PR показывает
  разницу результатов; ухудшение на golden set — причина не принимать правку, даже если она
  кажется разумной.

### Принципы оценки

Не пересматриваются молча — только решением владельца:

1. Отсутствие сигнала — не провал: «недостаточно данных», а не низкий балл.
2. Балл ставится только под дословную цитату из лога с номером сессии и хода; цитата
   проверяется поиском, а не памятью модели.
3. Две ступени всегда: сборщики по пачкам приносят доказательства без баллов, один оценщик
   сводит их.
4. Ничего не срезается: пачка — это разбиение лога, а не выборка из него.
5. Профиль человека меняет формулировку, но не балл. Прошлые баллы оценщику не подаются.
6. Баллы, уровни и служебные id в текст ревью не попадают никогда. Баллы и уровень адресату
   видны в личном отчёте и в сводке режима self по умолчанию; `show_scores: false` или
   `report --trend` оставляет только динамику ↑ → ↓ ◇.
7. Рекомендация — действие с адресом и ценой, а не диагноз.
8. Людей никогда не сравнивают между собой: каждый — против своего прошлого периода.
9. Логи сдаются добровольно и на оценку результата работы не влияют.
10. Счётчики и пороги считает скрипт, а не модель; «не измерено» — это `null`, а не 0.
11. Человек смотрит текст и выгрузку глазами перед отправкой.

## Откуда приходят предложения

- **GitHub Issues** по шаблонам: предложение, ошибка, утечка приватности
  (`.github/ISSUE_TEMPLATE/`).
- **GitHub Discussions** — вопросы, идеи без готового предложения, рассказы об использовании.
  Почты нет.
- **Предложения из плагина.** Скилл, упёршийся в ограничение плагина, с согласия
  пользователя пишет файл в `.retropair/improvements/` его проекта; пользователь сам
  отправляет его как issue. Автоотправки нет.

Разбор: дедупликация по паре «компонент + симптом», приоритет, решение — поменять дефолт,
поправить скилл или шаблон, поправить движок или отклонить с объяснением. Принятое
предложение отмечается в CHANGELOG строкой `внедрено: imp-…`.

Issue с утечкой приватности — первым приоритетом. Если в issue всё же вложены логи, имена
или ключи — скрыть содержимое и попросить автора переписать без данных.

## Релиз

Разработка идёт в отдельном репозитории; дистрибутив — репозиторий-зеркало, в который
копируется только папка плагина. Пока зеркало не синхронизировано и тег не поставлен, релиза
нет. Порядок жёсткий, любой отказ останавливает релиз:

1. **Гейты чистоты** на папке плагина в релизном режиме: нет ссылок на внутренние папки
   разработки, нет личных данных, путей домашних папок и e-mail, нет служебной нумерации задач,
   нет незаполненных заглушек, манифесты валидны (`claude plugin validate`), хост видит все
   скиллы и агентов, версии совпадают. Пропущенный гейт — не зелёный.
2. **Тесты** — полный прогон `scripts/tests` зелёный.
3. **Бамп версии** во всех четырёх местах (таблица ниже) одним числом, строго больше текущей.
4. **CHANGELOG**: пункты из `## [Unreleased]` переносятся в секцию `## [X.Y.Z] — ГГГГ-ММ-ДД`,
   `## [Unreleased]` остаётся первой и пустой. Содержание релиза пишет человек.
5. **Зеркало**: отдельный клон с чистым деревом; в него копируются отслеживаемые git файлы
   плагина, лишнее удаляется, один коммит `retropair X.Y.Z`. Символическая ссылка в зеркале
   не используется как путь записи.
6. **Приёмка зеркала** теми же гейтами.
7. **Тег** `vX.Y.Z` в зеркале, публикация ветки и тега. Бамп версии в репозитории разработки
   коммитится отдельным коммитом.

После публикации — проверка установки из GitHub в чистой папке: `/plugin marketplace add`,
`/plugin install`, список плагинов показывает новую версию и четыре скилла, отчёт демо
собирается; затем удалить плагин и маркетплейс.

### Версия — в четырёх местах

| Файл | Поле |
|---|---|
| `.claude-plugin/plugin.json` | `version` |
| `.claude-plugin/marketplace.json` | `metadata.version` |
| `.claude-plugin/marketplace.json` | `plugins[0].version` |
| `scripts/lib/version.py` | `__version__` |

Гейт `versions` сверяет все четыре; CHANGELOG сверяет релиз. Версии — SemVer: MAJOR —
несовместимое изменение формата состояния или CLI, MINOR — новые команды и поля,
PATCH — исправления.

## Владельцы конвенций

У каждой конвенции один файл-владелец: правило описано там, остальные ссылаются.

| Конвенция | Файл-владелец |
|---|---|
| Команда CLI = файл `scripts/lib/cmd_<команда>.py` с `register(subparsers)` и необязательным `doctor_lines(root)`; `sr.py` не правится | `scripts/lib/registry_cmds.py` (докстринг) |
| Коды выхода 0/1/2 и формат ошибки `retropair: <что>: <почему> (<параметры>)` через `SrError(message, code)` | `scripts/lib/workspace.py` |
| Раскладка `.retropair/` и `~/.retropair/`, кто что пишет, атомарная запись, блокировка | [STATE.md](STATE.md) |
| Поля `config.json` и карточки; только необязательные добавления | `references/schemas/config.json`, `references/schemas/person.json` |
| Дефолтные значения конфига и карточки | `templates/config.template.json`, `templates/person.template.yaml`, `templates/_default.yaml` |
| Строки интерфейса и отчётов (ru/en): секция → ключ → `{"ru", "en"}`, одна запись на строку, служебных полей нет | `references/i18n.json` |
| README и README.ru — одинаковый список разделов `##` в одном порядке, правятся вместе; три страницы `docs/en/` — пары к страницам `docs/ru/` с тем же именем; CHANGELOG — новое под `## [Unreleased]` (первая секция); TESTING — раздел на область, строка на тестовый файл | сами эти файлы; порядок разделов README — `scripts/tests/test_docs.py` |
| Версия | таблица выше |
| Запрещённые слова и ссылки, e-mail, версии, манифесты | гейты чистоты в репозитории разработки (шаг 1 релиза) |

## Анонимность

Ни в коде, ни в документации, ни в тестовых данных плагина нет реальных имён, хэндлов,
e-mail и цитат из чужих логов. Фикстуры — вымышленные люди и пути `/home/user/…`. Принятое
из issues переписывается без данных автора. Гейты чистоты проверяют это перед каждым
релизом.
