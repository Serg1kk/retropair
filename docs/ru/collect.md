# Сбор логов: откуда sessionretro берёт сессии и что из них вычищает

Оценка работы с агентом строится по логам сессий. Прежде чем что-то оценивать, sessionretro
собирает эти логи в одно место: находит их там, где их пишут Claude Code и SpecStory, вычищает
секреты и личные данные и кладёт очищенные копии в workspace проекта. Всё это делает одна
команда:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

В Claude Code то же самое можно попросить словами («собери логи сессий») — сработает скилл
`collect`. Сбор идёт локально, в сеть ничего не уходит (кроме `git pull`, если вы сами добавили
источник `git`).

Сбор безопасен для повтора: исходные логи не меняются никогда, неизменные копии не
переписываются, и запускать команду можно сколько угодно раз.

## Откуда берутся логи

Где искать логи, команда узнаёт из поля `sources` в `.sessionretro/config.json`. После
`init` там уже стоят два источника — сессии Claude Code и выгрузки SpecStory этого проекта:

```json
"sources": [
  {"type": "specstory", "path": ".specstory/history"},
  {"type": "claude-jsonl", "project": "auto"}
]
```

| Тип | Что читает | Настройка |
|---|---|---|
| `claude-jsonl` | сессии Claude Code: файлы `*.jsonl` в `~/.claude/projects/<папка проекта>/`, вместе с сессиями сабагентов | `"project": "auto"` — текущий проект; или абсолютный путь к другому проекту |
| `specstory` | markdown-выгрузки SpecStory, все `*.md` в папке и подпапках | `"path"` — папка относительно корня проекта |
| `dir` | любая папка с логами: `.md`, `.markdown`, `.txt`, `.jsonl` (подходит для ручного экспорта) | `"path"` — относительный или абсолютный |
| `git` | репозиторий с логами другого человека: плагин клонирует его в `~/.sessionretro/clones/` и при следующем сборе делает `git pull` | `"url"`, необязательно `"branch"`; только режимы team и course |

Источники можно добавлять и в карточку человека (`sources:` в `.sessionretro/people/<id>.yaml`),
тогда логи из них считаются логами этого человека. У источника в `config.json` владелец
определяется так: поле `"person": "<id>"`, если оно есть; иначе единственная карточка
workspace (в режиме self это вы). Если карточек несколько, а `person` не указан, сбор
остановится с ошибкой и попросит его указать.

Пример для команды — у каждого свой репозиторий с логами:

```yaml
# .sessionretro/people/alex.yaml
sources:
  - type: git
    url: git@github.com:example/alex-logs.git
```

Источник, папки которого нет (SpecStory ещё не ставили, Claude Code в проекте не запускали),
не ошибка: он пропускается со строкой в предупреждениях. Типы `codex-jsonl` и `cursor-jsonl`
в версии 0.1 не поддерживаются — логи Codex и Cursor собираются через SpecStory.

**Согласие.** Логи человека собираются, только пока он не против. Если в карточке стоит
`consent:` → `logs: false`, `collect` не читает ни один его источник (ни из карточки, ни из
`config.json` с его `person`) и пишет в предупреждения «`<id>`: нет согласия на логи
(consent.logs: false), источники пропущены». Снапшоты, собранные раньше, остаются в
`logs/<id>/`, но в инвентаре становятся исключёнными (`excluded_by: consent`), в пачки и
оценку не идут, а `sr.py batches <id>` отказывает с текстом «нет согласия на логи»; сами файлы
плагин не удаляет — предупреждение называет их число, удалить папку можно руками. Вернули
`logs: true` — эти сессии снова новые; исключения, поставленные оценкой, при этом остаются.
Карточка без блока `consent` (так обычно в режиме self) собирается как обычно; значение,
отличное от `true`/`false`, — ошибка. Сколько карточек без согласия, показывает
`sr.py doctor` (строка `people_without_consent`).

**Claude Code хранит свои логи ограниченное время** (по умолчанию около 30 дней, настройка
`cleanupPeriodDays` в `~/.claude/settings.json`; текущее значение показывает `sr.py doctor`).
Копия, которую сделал `collect`, остаётся в workspace и после того, как Claude Code удалит
исходник. Поэтому собирать логи стоит регулярно — проще всего включить хук (ниже).

Готовые рецепты для конкретных сред и агентов (JetBrains, VS Code, Cursor, Codex, терминальные
агенты, ручной экспорт) — в [инструкциях по связкам](../../references/collector-instructions/README.md).

## SpecStory

[SpecStory](https://specstory.com) — отдельная программа, которая выгружает сессии разных
агентов (Claude Code, Codex, Cursor, Antigravity) в markdown-файлы в папку
`.specstory/history/` проекта. sessionretro работает и без неё: для Claude Code хватает
источника `claude-jsonl`. SpecStory нужна для других агентов и для тех, кто хочет видеть
сессии в читаемом виде.

Если в источниках есть `specstory` и программа установлена (версия 2.6.0 или новее), `collect`
перед сбором сам запускает `specstory sync` в корне проекта. Каких агентов выгружать, задаёт
`hook.providers` в конфиге или флаг `--provider`; по умолчанию — `claude`:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect --provider claude --provider codex
```

Нет SpecStory, версия старее 2.6.0 или выгрузка упала — сбор не останавливается: в сводке
строка `specstory: …` с причиной, а собираются уже лежащие файлы.

**SpecStory без облака.** По умолчанию SpecStory умеет синхронизировать сессии в своё облако и
отправлять аналитику. Для логов, в которых лежит ваш код, это лишнее. Готовый конфиг, в котором
облако, аналитика, проверка версий и телеметрия выключены, а встроенная редакция секретов
включена, — [specstory-config.toml](../../references/collector-instructions/specstory-config.toml).
Куда его положить, написано в инструкции вашей связки.

## Команда `collect`

```bash
cd ~/work/my-app
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

```text
collect: 2 записей в инвентаре (/home/user/work/my-app/.sessionretro/logs-index.json)
новых: 2 · выросших: 0 · без изменений: 0 · дублей: 0 · пропавших: 0 · исключённых: 0
specstory: specstory sync claude: ок
санитайзер:
- ai-logs/2026-09-01_10-00-00Z-fix-login-bug.md: home_path 3; имён заменено 0
- ai-logs/cc-scrollback.txt: code_secret 1, home_path 1; имён заменено 0
*.orig найдено (не взяты): 1 · context-report (не взяты): 0 · слаг-файлов SpecStory: 1
предупреждения:
- источник 3 конфига: папки нет, источник пропущен (claude-jsonl: ~/.claude/projects/-home-user-work-my-app)
last_snapshot_at: 2026-09-27T16:58:34Z
```

Что в сводке:

- **первые две строки** — сколько сессий в перечне и в каком они статусе (см. «Статусы» ниже);
- **specstory** — прошла ли выгрузка SpecStory;
- **санитайзер** — по каждому файлу, где что-то вычищено: какие правила сработали и сколько раз,
  сколько имён заменено. Файлы без срабатываний не показываются. Пути здесь, в предупреждениях и
  в файлах `.sessionretro/` записаны без логина: внутри проекта — от его корня, внутри домашней
  папки — как `~/…`;
- **`*.orig`, context-report, слаг-файлы** — счётчики файлов, о которых стоит знать (ниже);
- **предупреждения** — что пропущено и почему; сбор при этом прошёл;
- **last_snapshot_at** — когда обновлён перечень.

Флаги:

| Флаг | Что делает |
|---|---|
| `--provider <имя>` | какого агента выгружает `specstory sync`; можно повторять |
| `--json` | сводка одним JSON-объектом — для скриптов |
| `--quiet` | при успехе ничего не печатать (так сбор запускает хук); ошибки всё равно в stderr |
| `--replace <имя>` | перезаписать снимок `<имя>` из `logs/<id>/`, даже если новый короче или не похож на лежащий (нужно после ручной чистки исходника); можно повторять |
| `--workspace <папка>` | проект, если он не в текущей папке |

Коды выхода: `0` — сбор прошёл (предупреждения не ошибка), `1` — данные не сошлись (битый
шаблон в `sanitize.extra_patterns`, источник без `person` при нескольких карточках, ошибка
`git`), `2` — неверный вызов, например нет workspace. Workspace ещё нет — создайте его
скиллом `/sessionretro:setup` или командой `init` (см. [workspace.md](workspace.md)).

Два одновременных сбора в одном проекте не мешают друг другу: второй ждёт, пока закончится
первый. Ручной запуск ждёт до 10 секунд и, не дождавшись, выходит с кодом `1` и сообщением о
блокировке — просто повторите команду позже. Фоновый сбор хука (`--quiet`) ждёт до 120 секунд:
несколько терминалов одного проекта часто закрываются почти одновременно. Не дождался — пишет
в `collect.log` строку «сбор уже идёт» и выходит с кодом `0`.

Повторный сбор быстрый: исходник, который не менялся с прошлого раза, не разбирается и не
чистится заново.

## Что появляется в workspace

```text
.sessionretro/
├── logs/<id человека>/
│   ├── <ключ сессии>.md       # очищенная копия markdown-лога (SpecStory, экспорт)
│   ├── <ключ сессии>.jsonl    # очищенная копия сессии Claude Code
│   └── .meta.json             # откуда взят каждый снимок и что вычистил санитайзер
├── logs-index.json            # перечень собранных сессий со статусами
└── collect.log                # вывод фоновых сборов (пишет хук)
```

- Копия называется по ключу сессии (её идентификатору, если он есть в логе), а не по имени
  исходного файла.
- Копия сессии Claude Code компактная: только реплики, ответы агента и вызовы инструментов
  главной сессии и сабагентов. Скрытые рассуждения модели в копию не попадают (остаётся только
  их длина), длинные выводы инструментов обрезаются до 4000 символов с пометкой.
- Если исходник стал короче лежащей копии (его перезаписали или обрезали), копия не
  затирается — в предупреждениях строка «снапшот … не перезаписан» с готовой командой. Если вы
  укоротили исходник намеренно, например вырезали ход с приватным текстом, повторите сбор с
  флагом `--replace <имя снимка>`: копия перезапишется, и вырезанное из неё уйдёт.
- Одна и та же сессия из двух источников — одна копия из более полного файла и строка
  «дубль ключа» в предупреждениях.
- Под одним ключом оказалась другая сессия (например, два ручных экспорта с одинаковым началом):
  лежащая копия не затирается, новая сохраняется рядом с суффиксом `_<8 знаков>` в имени, в
  предупреждениях строка «другая сессия».

**Коммитить ли `logs/`.** В режиме self, для себя, папку `.sessionretro/logs/` не коммитьте: даже
очищенная, это переписка с агентом (подробнее в [workspace.md](workspace.md), раздел «Что
коммитить в git»). Если логи смотрит ревьюер (режимы team и course), передать ему можно папку
`.sessionretro/logs/<ваш id>/`: снимки в ней уже очищены, а пути в `.meta.json` записаны без
логина. Перед передачей пролистайте снимки глазами — название клиента в свободном тексте видите
только вы.

## Статусы сессий

Каждая сессия в перечне `logs-index.json` имеет статус. Он нужен оценке: чтобы не разбирать
одно и то же дважды и заметить, что в старой сессии появилось новое.

| Статус | В сводке | Что значит |
|---|---|---|
| `new` | новых | сессия ещё не оценивалась. Остаётся новой при каждом сборе, пока её не разберёт оценка |
| `grown` | выросших | сессию уже оценивали, а после этого в ней появились новые ходы — оценке достанется только продолжение |
| `unchanged` | без изменений | сессия оценена, новых ходов нет |
| `duplicate` | дублей | та же сессия, что и другая запись (например, выгрузка SpecStory и JSONL Claude Code одной сессии); в оценку идёт одна — предпочтительно JSONL, в нём больше данных |
| `gone` | пропавших | копию удалили из `.sessionretro/logs/` руками; запись остаётся в перечне для истории |
| `excluded` | исключённых | оценка решила сессию не разбирать (например, в ней пара реплик). Если сессия потом вырастет, она снова станет новой |

«Выросла» считается только по числу ходов. Если файл поменялся, а ходов не прибавилось
(перевыгрузка, другие пустые строки), сессия остаётся «без изменений».

Пересчитать перечень по уже лежащим копиям, не трогая источники:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" inventory
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" inventory --json
```

## Санитайзер: что вычищается

Лог сессии — это не только ваша переписка с агентом, но и всё, что агент читал: код, конфиги,
вывод команд. Поэтому каждый лог по дороге в `.sessionretro/logs/` проходит через встроенный
санитайзер. Он работает офлайн и детерминированно: одинаковый лог всегда чистится одинаково.
Исходные файлы он не трогает — меняется только копия.

Найденное заменяется меткой в квадратных скобках. Названия правил — те же, что в сводке
`collect`.

| Правило | Что ловит | Метка |
|---|---|---|
| `aws_key` | ключи доступа AWS | `[AWS_KEY]` |
| `github_token`, `github_pat` | токены GitHub | `[GITHUB_TOKEN]` |
| `anthropic_key`, `openai_key`, `stripe_key`, `google_key` | API-ключи Anthropic, OpenAI, Stripe, Google | `[API_KEY]` |
| `slack_token` | токены Slack | `[SLACK_TOKEN]` |
| `jwt` | JWT-токены | `[JWT]` |
| `private_key` | приватные ключи (`-----BEGIN … PRIVATE KEY-----`) целиком | `[PRIVATE_KEY]` |
| `json_secret` | пароль, токен, ключ в JSON и словарях, когда ключ в кавычках: `"password": "…"`, экранированный JSON в строке команды `\"password\":\"…\"`, `'api_key': '…'`, `cfg["token"] = "…"`; заменяется только значение, JSON остаётся валидным. Ссылки (`$VAR`, `${VAR}`, `os.environ[…]`, `process.env.…`) и пустые значения не трогаются | `[SECRET_ASSIGNMENT]` |
| `code_secret` | пароль, токен, ключ в присваивании с кавычками: `DB_PASSWORD = "…"`, `api_key: '…'` | `[SECRET_ASSIGNMENT]` |
| `env_secret` | то же без кавычек: `export API_TOKEN=…` | `[SECRET_ASSIGNMENT]` |
| `password_field` | строка, которую вводят в поле пароля (автозаполнение формы в браузере, UI-тесты): после селектора поля (`[name=password]`, `input[type=password]`, `#pwd`, `getByLabel('Password')`) в той же инструкции — `.value = '…'`, `.fill('…')`, `.type('…')`, `send_keys('…')`; `page.fill('#password', '…')`; переменная поля — `pass.value = '…'`, `setVal(pass, '…')` | `[PASSWORD]` |
| `conn_string` | строки подключения с паролем: `postgres://user:пароль@host` | `[CONNECTION_STRING]` |
| `password_text` | пароль после метки в обычном тексте, списке или таблице (ячейка «Пароль», значение в соседней): `Пароль: …`, `- pwd — …`, `пароль Abc123` (после пробела — только значение с буквой и цифрой); метки пароль, password, passwd, pass, pwd | `[PASSWORD]` |
| `totp_secret` | секрет 2FA/TOTP после метки: `2FA: …`, `Authenticator Key: …`, `ключ аутентификатора — …`; метки 2FA, TOTP, OTP, MFA, authenticator, secret, секрет; значение с цифрой, base32-группы через пробел или дефис берутся целиком | `[OTP_SECRET]` |
| `base32_secret` | ключ аутентификатора без метки: отдельный токен base32 в верхнем регистре от 16 символов, сплошной или группами по 4 (`ABCD EFGH …`), с буквой и цифрой 2–7 | `[OTP_SECRET]` |
| `email` | адреса почты | `[EMAIL]` |
| `phone` | телефоны | `[PHONE]` |
| `passport_by_ru` | номера паспортов в формате `1234 567890` | `[DOC_ID]` |
| `card` | номера банковских карт | `[CARD]` |
| `iban` | номера счетов IBAN | `[IBAN]` |
| `home_path` | логин в домашних путях macOS и Linux: `/home/alice/…` → `/home/[USER]/…`; логин — любые символы до `/`, пробела или кавычки, кириллица тоже | `[USER]` |
| `home_path_win` | то же для Windows в любом регистре: `C:\Users\alice\…`, экранированные слэши (`\\`), смешанные и прямые слэши после буквы диска, пути WSL под `/mnt/c/`; логин с пробелом берётся целиком | `[USER]` |
| `home_path_munged` | логин в именах папок сессий Claude Code: `-Users-alice-…` | `[USER]` |
| `internal_host` | адреса внутренних сайтов: `https://….internal`, `.local`, `.corp`, `.intranet`, `.lan` | `[INTERNAL_URL]` |
| `private_ip` | внутренние IP-адреса: `10.…`, `192.168.…`, `172.16–31.…` | `[PRIVATE_IP]` |
| `names` | имена людей и ваши названия (ниже) | `[NAME]` |
| `local_user` | ваш логин и имя домашней папки там, где они стоят вне путей: вывод `ls -l`, приглашение терминала | `[USER]` |
| `extra` | ваши собственные шаблоны (ниже) | `[REDACTED]` |

Заглушки из документации не вырезаются: `PASSWORD="test"`, `${TOKEN}`, `<your-key>`,
`process.env.API_KEY` останутся как есть. Но заглушка должна быть значением целиком:
`PASSWORD="test-prod-2026"` будет вырезан. Слова после метки, не похожие на значение, тоже
остаются: «пароль не нужен», `Password: required`, «2FA: включена». Идентификаторы сессий и
сообщений (UUID) не принимаются за телефоны и номера карт.

**Имена.** Регулярное выражение не отличит фамилию от обычного слова, поэтому имена санитайзер
берёт из двух мест:

- из карточек людей (`name` в `.sessionretro/people/*.yaml`): имя целиком и каждое слово из
  трёх и более букв (короче не берутся: имя «Я» в карточке `me` иначе вырезало бы каждое «я»);
- из `sanitize.names` в `config.json` — сюда впишите всё своё, что не должно попасть в логи:
  компанию, клиентов, коллег, внутренние системы.

Имена ищутся целым словом и без учёта регистра. Граница слова — любой символ, кроме буквы и
цифры, в том числе `_`: имя найдётся и в `alice_notes`, и в `repo__alice`, но не внутри
`malice`.

**Свои шаблоны.** `sanitize.extra_patterns` — регулярные выражения (синтаксис Python), всё
совпавшее заменяется на `[REDACTED]`. Например, номера задач внутреннего трекера:

```json
"sanitize": {
  "names": ["Acme", "Project Falcon"],
  "extra_patterns": ["INT-\\d+", "falcon-[a-z]+\\.acme\\.io"]
}
```

Шаблон с ошибкой останавливает сбор с кодом `1` и показывает, какой именно шаблон сломан.

**Поменяли настройки — копии перечистятся.** Добавили имя в `sanitize.names`, новую карточку или
шаблон в `extra_patterns` — просто повторите `collect`. Каждая копия помнит отпечаток правил,
которыми её чистили; если он другой, копия чистится заново — из исходника, а если исходника уже
нет (JSONL Claude Code удаляются через 30 дней), то сама копия.

Автоматика ловит известные форматы, а название клиента в свободном тексте видите только вы.
Перед тем как отдавать логи кому-то, пролистайте хотя бы одну копию в `.sessionretro/logs/`
глазами.

## Файлы `*.orig`, слаг-файлы и context-report

- **`*.orig`** — сырые копии, которые остаются после ручной чистки лога (так их оставляют
  некоторые редакторы и скрипты). В них то, что вычищали, поэтому sessionretro их не берёт и
  сам никогда не пишет — только считает в сводке. Такие файлы не коммитьте и никому не
  отдавайте.
- **Слаг-файлы SpecStory** — выгрузки с именем вида `2026-09-01_10-00-00Z-fix-login-bug.md`:
  SpecStory называет файл по началу первого промпта. Они собираются как обычные логи, но копия в
  `.sessionretro/logs/` называется по ключу сессии, так что текст промпта в её имя не попадает.
- **`context-report*`** — служебные отчёты о контексте; в сбор не берутся, только считаются.

## Хук: сбор после каждой сессии

Чтобы не запускать сбор руками, у плагина есть хук SessionEnd: когда сессия Claude Code
заканчивается, он запускает тот же `collect` в фоне и сразу выходит. Сессия не ждёт сбора, а в
окно Claude Code хук ничего не пишет.

- Хук работает только в проектах с `.sessionretro/config.json` (в текущей папке или выше). В
  остальных проектах он завершается за миллисекунды и ничего не делает.
- Сбор запускается только для workspace из вашего реестра `~/.sessionretro/workspaces.json`
  (его пишет `/sessionretro:setup`): путь в реестре совпадает с корнем проекта. Склонированный
  чужой репозиторий с закоммиченным `.sessionretro/config.json` сбор не запустит: иначе чужой
  конфиг мог бы собрать ваши логи других проектов. Хук тогда пишет в stderr строку
  `workspace не зарегистрирован … запустите /sessionretro:setup` и выходит, в проект ничего не
  пишет. Чтобы собирать логи в этом проекте, запустите в нём `/sessionretro:setup`.
- Включён он или нет, решает `hook.enabled` в `config.json`. После `init` хук включён.
  Включить или выключить его можно в `/sessionretro:setup` или прямо в конфиге:

  ```json
  "hook": {"enabled": false, "providers": ["claude"]}
  ```

- `hook.providers` — каких агентов выгружает SpecStory при фоновом сборе.
- Вывод фоновых сборов и их ошибки пишутся в `.sessionretro/collect.log`: строка
  `<время> hook session=<id>` перед каждым запуском, дальше то, что напечатал сбор. Файл сам
  обрезается, когда перерастает 1 МБ (остаются последние 200 КБ).

Если после сессии свежие логи не появились, первым делом загляните в `collect.log`.

## Ручной режим

Хук не обязателен. Можно выключить его (`"enabled": false`) и собирать, когда нужно:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

Если ваш агент не пишет логи сам, сохраните сессию вручную (в Claude Code — команда `/export`,
в других агентах — экспорт переписки в markdown) в папку проекта, например `ai-logs/`, и
добавьте её источником:

```json
{"type": "dir", "path": "ai-logs"}
```

Как именно экспортировать из вашей среды, написано в
[инструкциях по связкам](../../references/collector-instructions/README.md).

Посмотреть, как плагин понял отдельный лог, — без workspace и без записи куда-либо:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" normalize ai-logs/session.md --stats
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" normalize ai-logs/session.md --tools-map
```

`--stats` покажет формат, число ходов и метрики, `--tools-map` — какие инструменты агент
вызывал по ходам. Полный список флагов — `normalize --help`.

## Windows

На Windows сбор в версии 0.1 не поддерживается: блокировка файлов, на которой держится
`collect`, там не работает, и команда остановится с понятной ошибкой. SpecStory под Windows тоже
нет. Путь для Windows — ручной экспорт сессий через `/export` и сбор на машине с macOS или
Linux, подробно — в [windows.md](../../references/collector-instructions/windows.md).
