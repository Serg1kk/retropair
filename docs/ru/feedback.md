# Предложения авторам плагина: что записывается и как отправить

Иногда работа упирается не в ваши данные, а в сам плагин: команда чего-то не умеет, формат не
читается, пришлось обходить руками. Тогда скилл RetroPair доводит задачу обходом и одной
репликой предлагает записать предложение для авторов плагина. Согласились — в проекте появляется
короткий обезличенный файл. Сам плагин ничего никуда не отправляет, почты у него нет: предложения
уходят, только когда вы сами соберёте их в пакет и отправите issue на GitHub.

Посмотреть, что записано:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" improve list
```

```text
imp-20260927-collect-7fea · pending · collect
imp-20260927-setup-5a56 · sent · setup
```

## Когда плагин предложит записать

Скиллы `setup`, `collect`, `review` и `report` предлагают запись, только когда мешает плагин:

- нужной возможности нет — команда не умеет, формат не читается, шаблон не покрывает случай;
- скрипт или скилл сбоит воспроизводимо;
- пришлось обходить плагин руками, чтобы закончить работу.

Порядок всегда один: сначала обход, чтобы ваша задача была сделана, потом одна реплика — что
упёрлось, как обошли, что предлагается — и вопрос «Записать предложение для авторов плагина?».
Файл пишется только после вашего «да». Ответили «нет» — в этой сессии вопрос не повторится.

Не предлагается:

- по вкусу — тону, длине и стилю текста: это настройки карточки и шаблона
  ([customize.md](customize.md));
- по ошибкам ваших данных (битый конфиг, нет логов): это сообщение об ошибке;
- в фоновых и неинтерактивных прогонах (хук, `claude -p`, `--no-ask`): там некому ответить;
- повторно, если такое же предложение (тот же компонент и симптом) уже записано — скилл назовёт
  его ID.

## Где лежат файлы и что внутри

Каждое предложение — файл `.retropair/improvements/imp-ГГГГММДД-<слаг>-<4 знака>.md` в вашем
проекте:

```text
# imp-20260927-setup-5a56

- **ID:** imp-20260927-setup-5a56
- **Компонент:** setup
- **Симптом и контекст:** setup-apply не принимает окно дат без метки
- **Локальный обход:** метку окна вписали руками в config.json
- **Предложение:** причина — ручная правка конфига; подход — метка по датам окна; критерий успеха — окно без метки проходит
- **Версия плагина:** 0.2.0
- **Дата:** 2026-09-27
- **Статус:** pending
```

Текст обезличивается при записи: пути внутри проекта становятся относительными, домашняя папка —
`~`, имена из карточек людей заменяются на `[NAME]`, e-mail — на `[EMAIL]`. Если после этого в
тексте всё равно остался путь с логином, e-mail или имя из карточек, файл не пишется, команда
выходит с кодом `1` и называет, что нашла. Файлы можно открыть и поправить руками — при сборке
пакета проверка повторится.

Записать предложение можете и вы сами, без скилла:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" improve add --component review --symptom "пачка из 200 ходов не влезла в лимит судьи" --workaround "разбили период на два" --proposal "причина — длинные сессии; подход — делить пачку автоматически; критерий успеха — период из 200 ходов проходит за один запуск"
```

`--slug` задаёт слово в ID (латиница через дефис); по умолчанию оно берётся из компонента.

## Что уходит в issue и что нет

Уходит только то, что вы видите в файлах предложений: компонент, обезличенный симптом, обход,
само предложение, версия плагина и дата.

Не уходит никогда и не должно появляться в тексте:

- логи сессий — ни целиком, ни фрагментами, даже очищенные;
- цитаты из сессий и тексты ревью, оценки;
- имена, хэндлы и e-mail людей, названия вашей компании, клиентов и проекта;
- пути вашей машины с логином, ключи, токены, внутренние адреса.

Автоматика ловит пути, почту и имена из карточек, но название клиента в свободном тексте видите
только вы. Перечитайте пакет перед отправкой.

## Собрать пакет: `improve pack`

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" improve pack
```

Команда собирает все `pending` в один файл `.retropair/improvements/pack-ГГГГММДД-<4 знака>.md`
(свой путь — `--out <файл>`), ещё раз проверяет его на пути, e-mail и имена, печатает пакет
целиком и готовую команду отправки. Сама она ничего не отправляет:

```text
пакет: /home/user/work/my-app/.retropair/improvements/pack-20260927-31f0.md
Ничего не отправлено. Перечитайте пакет выше; чтобы отправить, запустите команду ниже сами, затем отметьте: `improve sent <ID>…`
gh issue create --repo <репозиторий плагина> --label proposal --title 'RetroPair 0.2.0: предложений 1' --body-file /home/user/work/my-app/.retropair/improvements/pack-20260927-31f0.md
```

Репозиторий команда берёт из поля `repository` в `.claude-plugin/plugin.json` плагина. Нет
`pending`-предложений или в тексте нашлись личные данные — код `1`, пакет не пишется.

## Отправить

1. Перечитайте пакет — ровно этот текст уйдёт в issue.
2. Запустите напечатанную команду `gh issue create …` (нужен [GitHub CLI](https://cli.github.com)
   и вход `gh auth login`). Без `gh` — откройте на GitHub новый issue по шаблону «Proposal» и
   вставьте текст пакета.
3. Отметьте отправленные предложения, чтобы они не попали в следующий пакет:

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" improve sent imp-20260927-setup-5a56
   ```

## Когда предложение внедрят: `improve sync`

Принятое предложение авторы отмечают в CHANGELOG плагина строкой `внедрено: imp-…` под
заголовком версии. После обновления плагина выполните:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" improve sync
```

Внедрённые предложения получат статус `implemented (X.Y.Z)` и переедут в
`.retropair/improvements/archive/`. `--changelog <файл>` читает другой CHANGELOG.

| Статус | Что значит | Кто ставит |
|---|---|---|
| `pending` | записано, не отправлено | `improve add` |
| `sent` | вы отправили пакет | `improve sent <ID>…` |
| `implemented (X.Y.Z)` | внедрено в версии X.Y.Z, файл в `archive/` | `improve sync` |

Сколько предложений ждут отправки, показывает строка `improvements_pending` в `doctor`.

## Шаблоны issue

В репозитории плагина три шаблона issue:

| Шаблон | Файл | Когда |
|---|---|---|
| Proposal | `proposal` | улучшение оценки, текста, отчётов или настройки; пакет `improve pack` уходит сюда |
| Bug | `bug` | ошибка скрипта, скилла или отчёта: шаги, ожидание, текст ошибки `retropair: …`, версия плагина, ОС и python3 |
| Privacy | `privacy` | в текст, отчёт или лог попали личные данные или секреты |

**Утечка приватности** — отдельный шаблон и первый приоритет для авторов. В нём описывается,
**какого рода** данные просочились (путь, имя, ключ, e-mail) и **на каком шаге** (сбор,
санитайзер, текст человеку, HTML-отчёт), — без самих данных: не вкладывайте логи, имена и ключи
ни целиком, ни фрагментами.

Ошибку или утечку можно отправить и из терминала:

```bash
gh issue create --repo <репозиторий плагина> --label bug --title "collect: ошибка на пустой папке" --body-file bug.md
```

Нужен пример — придумайте его: вымышленное имя (`alex`), путь `/home/user/…`, синтетический лог из
трёх-четырёх ходов.
