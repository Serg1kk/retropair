# Переход с SessionRetro на RetroPair

RetroPair 0.2.0 продолжает историю продукта. Четыре скилла теперь вызываются как
`/retropair:setup`, `/retropair:collect`, `/retropair:review` и `/retropair:report`.
Основной вход CLI — `scripts/rp.py`; `scripts/sr.py` остаётся поддержанным.
Поля сохранённых оценок, ID рекомендаций и ID периодов сохраняют прежний контракт.

## Смена установленного плагина

Сначала завершите текущий сбор и ревью. Отключите сбор в старом workspace
(`hook.enabled: false` в `.sessionretro/config.json`) и закройте старую сессию Claude Code.
Перед переносом сохраните резервную копию workspace и изменённых проектных агентов.
Затем замените регистрацию плагина и маркетплейса в Claude Code:

```text
/plugin uninstall sessionretro@sessionretro
/plugin marketplace remove sessionretro
/plugin marketplace add Serg1kk/retropair
/plugin install retropair@retropair
/reload-plugins
```

Репозиторий дистрибутива остаётся приватным; вашему аккаунту GitHub нужен доступ.
Это инструкция ручного перехода, а не утверждение, что обновление существующей установки
проверено в вашем Claude Code. Удаление плагина не удаляет данные workspace.
Если вы отдельно прописывали SessionEnd-хук в настройках Claude, уберите старую запись
перед включением новой. Должен остаться один активный хук сбора RetroPair.

## Предпросмотр и перенос состояния

В командах используйте корень установленного плагина. `/path/to/project` замените на корень
проекта, а не каталог исходных логов. По умолчанию команда только показывает план:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" --workspace /path/to/project migrate
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" --workspace /path/to/project migrate --apply
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" --workspace /path/to/project migrate --global
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" --workspace /path/to/project migrate --global --apply
```

Перенос проекта перемещает `.sessionretro/` в `.retropair/`, глобальный перенос —
`~/.sessionretro/` в `~/.retropair/`. Содержимое файлов состояния сохраняется: карточки,
оценки и история баллов, одобрения и отзывы ревью, заметки ревьюера, рекомендации и вердикты,
инвентарь, очищенные снимки, свои шаблоны, язык, модели/effort и настройки хука.
Миграция не пересчитывает оценки, не добавляет прогонов и не переписывает исходные логи агентов.

Если существуют оба каталога, команда отказывается их перезаписывать или объединять.
Сохраните оба, сравните содержимое и устраните конфликт перед повторной попыткой.
Повторный запуск после завершённого переноса не дублирует историю. Не собирайте логи сразу
в обе копии. Перемещение каталога не очищает файлы, добавленные вручную: проверьте workspace
перед передачей кому-либо. Исходные сырые логи остаются на своих местах; миграция их не копирует.

После переноса выполните `/retropair:setup`, чтобы проверить регистрацию, агентов,
настройки хука и `.gitignore`, затем `doctor` и пересборку отчётов:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" --workspace /path/to/project doctor
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" --workspace /path/to/project report
```

Перед сбором нового периода убедитесь, что видны прежние периоды, одобрения и рекомендации.
Проектная команда `migrate --apply` сохраняет старые правила `.gitignore` и до переноса
добавляет стандартную защиту новых путей, эквиваленты своих legacy-правил и правила
для файлов аудита/блокировки. Аудит `.retropair-migration.json` содержит имена, размеры
и хэши файлов, без содержимого; права — только для владельца (`0600`). Предпросмотр
не меняет `.gitignore`. Сохраняйте legacy-защиту, пока есть старый workspace или резервная копия.

## Изменённые проектные агенты

Новые workspace используют `.claude/agents/retropair-log-collector.md`,
`retropair-log-judge.md` и `retropair-feedback-critic.md`. Сохраняйте изменённые
`sessionretro-*.md` до проверки синхронизации агентов. Не устраняйте предупреждения миграции
через `agents write --force` без просмотра и резервной копии своих правок: этот флаг явно
перезаписывает промпты агентов. Подробнее: [customize.md](customize.md).

## Сайт и будущие команды

Канонический адрес продукта — [retropair.dev](https://retropair.dev). Реализация сайта,
включая отдельные страницы документации, приватности и пилотов, — следующая задача.
Доступный справочник пока находится в [локальной документации](../README.md).
`/retropair:retro` — запланированный shortcut, доступного скилла пока нет. Он не должен
автоматически одобрять ревью в team/course.
