# Ревью периода: как запускать и что получится

Ревью — это один прогон оценки на человека за период: логи сессий читают две ступени агентов,
результат записывается в историю, и получается текст с тем, что стоит попробовать иначе. Как
устроена сама оценка, читайте в [how-it-works.md](how-it-works.md), что смотрится по каждой
оси — в [axes.md](axes.md).

Перед первым ревью нужны workspace и карточки людей ([workspace.md](workspace.md)) и собранные
логи (скилл `collect`).

## Как запустить

В Claude Code попросите своими словами («проведи ретро за период», «оцени мои сессии») или
вызовите скилл явно:

```text
/sessionretro:review alex
/sessionretro:review --all --task-summary "перенос выгрузки отчётов на новую очередь"
/sessionretro:review me --no-ask
```

Без участия человека, например по расписанию:

```bash
claude -p "/sessionretro:review --all --no-ask"
```

## Аргументы

| Аргумент | Что делает |
|---|---|
| `<person>` | id карточки: ревью по одному человеку (в режиме self это `me`) |
| `--all` | ревью по каждому, у кого есть новые или продолженные сессии; остальных оно не касается |
| `--task-summary "…"` | одна нейтральная строка о том, над чем шла работа. Без критериев приёмки: оценивается, как человек сам поставил задачу агенту, а не насколько он совпал с чужими ожиданиями |
| `--no-ask` | ни одного вопроса: о работе — «нет», метка периода выводится сама. Где без ответа дальше нельзя, ревью по человеку останавливается и причина видна в итоге |
| `--approve <person> [run]` | только одобрить готовый черновик, без новой оценки |

Без `--no-ask` скилл спросит не больше двух вещей: строку о работе, если её не дали, и что
делать с незаписанным результатом прошлого запуска, если такой найдётся.

## Что происходит

1. Скилл находит людей с новыми или продолженными сессиями. Новых логов нет — ревью по
   человеку нет, и это не вывод о нём.
2. Сессии периода делятся на пачки по времени. Ничего не срезается: каждая годная сессия
   попадает ровно в одну пачку. Если за период у человека только короткие сессии, оценки нет:
   в итоге строка «данных мало», а сессии отмечаются исключёнными без прогона и в следующий
   раз не подаются, пока не вырастут.
3. Сборщики фактов читают пачки параллельно и выписывают цитаты. Скрипт проверяет, что в их
   выходе нет оценок и все восемь осей на месте.
4. Оценщик сводит факты, ставит оценки под цитаты, выносит вердикты по прошлым рекомендациям
   и пишет части текста.
5. Скрипт проверяет результат (оценка только под цитату, «мало данных» без оценки, запреты
   текста) и записывает прогон в историю `.sessionretro/runs/process-reviews.json`. Сессии
   отмечаются оценёнными и в следующий раз не подаются повторно; продолженная сессия
   подаётся только новым хвостом. Когда период задан по дате запуска (режим `run`), метку
   ставит сам скрипт: `run-<ГГГГММДД>` по дате UTC, а второй и следующие ретро за те же
   сутки получают `-2`, `-3` и считаются отдельными периодами, а не повтором первого.
6. Скрипт считает уровень по формуле и собирает текст по шаблону.
7. Сверка: у каждого прогона есть текст, уровень и отметки сессий.

В конце скилл показывает итог по каждому человеку: сколько сессий оценено и исключено, путь к
тексту и его статус. Оценок и уровней в итоге нет (в режиме self — только с `show_scores`),
людей между собой он не сравнивает.

## Что видит оценщик, а что не подаётся

Оценщик получает факты сборщиков, пути к логам для сверки цитат, строку о работе, открытые
рекомендации прошлых периодов и короткий срез карточки: роль, грейд, опыт, стек и как писать
текст. Сборщикам фактов карточка не подаётся вовсе.

Что не подаётся никому из агентов:

- прошлые оценки и уровни: иначе новая оценка подгоняется под старую;
- заметки и впечатления ревьюера о человеке;
- критерии приёмки задачи и то, что человек «должен был» сделать;
- оценка кода или другого результата работы;
- файлы правил проекта (CLAUDE.md, AGENTS.md): это оценка артефакта, а не логов;
- логи и тексты других людей.

## Текст ревью

Файл `.sessionretro/reviews/<person>/<run_id>.md` состоит из трёх частей:

- **служебная часть** для ревьюера: сколько сессий и пачек, что не вошло и почему,
  предупреждения оценщика;
- **текст для человека** между двумя линейками `---`: вступление, один-три пункта «что
  попробовать иначе» с датой, цитатой и действием, разбор по восьми осям. Только эта часть
  уходит адресату;
- **досье** для ответов на вопросы «а где это было?»: таблица сессий, номера рекомендаций,
  вердикты по прошлым, команды, чтобы открыть нужный кусок лога.

Шаблон текста заменяемый: `feedback.template` в карточке, иначе шаблон плагина.

## Черновик и одобрение

| Режим | Статус нового текста |
|---|---|
| self | `approved` — вы и есть ревьюер |
| team, course при `reviewer_gate: true` | `draft` — текст уходит человеку только после чтения |
| team, course при `reviewer_gate: false` | `approved` |

Прочитали черновик и согласны — одобрите:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" approve alex
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" approve alex <run_id>
```

Без `<run_id>` одобряется последний действующий прогон человека. То же делает
`/sessionretro:review --approve alex`.

В team и course при `reviewer_gate: true` рекомендации из текста начинают учитываться только
после одобрения: пока текст черновик, человек их не получал, и следующее ревью не спрашивает,
последовал ли он им. `open-recs` показывает такие рекомендации отдельно (`pending_approval`),
а сводка ревью пишет, что вердикт по ним отложен.

Черновик не устраивает по фактам — не правьте цифры в истории руками. Если оценка неверна
целиком, отзовите прогон: он останется в истории помеченным как отозванный, а отметки его
сессий вернутся к состоянию до него, и следующее ревью подаст их снова. Номера рекомендаций
отозванного прогона не переиспользуются: новые рекомендации получат следующие свободные номера
(если оценщик взял занятый, запись сама перенумерует их и предупредит).

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" retract <run_id> --why "оценщик перепутал сессии"
```

Текст пересобрать после правки шаблона или карточки:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" render-review .sessionretro/runs/pending/alex/judge.json --person alex --run <run_id>
```

## Другие команды

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" open-recs alex          # открытые рекомендации
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" compare <run_a> <run_b>  # два прогона одного человека
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" verify                   # всё ли закрыто до конца
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" validate                 # история прогонов цела
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" self-test                # самопроверка движка оценки
```

`compare` полезен для замера воспроизводимости: насколько расходятся две оценки одного и того
же периода по осям и совпал ли уровень. Сравнивает он только прогоны одного человека.

`self-test` прогоняет тесты движка оценки, которые идут вместе с плагином, и печатает число
проверок и упавшие. Запускайте после обновления плагина или если результат выглядит странно.

## Коды выхода

У всех команд одинаковые:

- `0` — всё хорошо;
- `1` — данные не сошлись или не прошли проверку (например, оценка без цитаты, текст с
  запрещённым словом, прогон закрыт не до конца); что именно не сошлось — в тексте ошибки;
- `2` — неверный вызов: нет workspace, неизвестный человек, опечатка в аргументах.

Ошибка печатается одной строкой: что упало, почему и с какими параметрами.
