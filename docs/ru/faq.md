# Частые вопросы

Переходите с SessionRetro? Перед созданием нового workspace прочитайте [инструкцию миграции](migration.md).

## Плагин оценивает мой код?

Нет. RetroPair смотрит только на то, как вы ведёте агента: ставите задачу, проверяете
результат, держите решения за собой. Качество кода, архитектура, скорость работы и результат
задачи не оцениваются. Восемь осей — в [axes.md](axes.md).

## С какими агентами он работает?

Оценка запускается из Claude Code. Логи Claude Code читаются напрямую. Логи Cursor, Codex,
Antigravity CLI и других агентов собираются через выгрузки SpecStory или ручной экспорт в папку;
как это сделать для вашей среды — в
[инструкциях по связкам](../../references/collector-instructions/README.md).

Файлы сессий Codex и Cursor в их собственном формате (JSONL) в 0.2 напрямую не читаются: сбор
покажет предупреждение. Путь для них — SpecStory.

## Сколько это стоит и сколько длится?

Исторические замеры до ребрендинга, а не актуальные цены или гарантия стоимости:
с моделями по умолчанию (оценщик opus, сборщики sonnet) один период одного человека стоит около
3–4 $ и занимает 10–15 минут; период только из коротких сессий — 0,3–0,6 $. Это цифры сквозной
проверки на реальной работе. Оплачивается через ваш Claude Code:
подписку или ключ API. Дешевле — пресет «Экономно» в `/retropair:setup`, но цитат и тонких
мест будет меньше ([setup.md](setup.md), вопрос «Модели и effort»).

## Насколько оценке можно верить?

Оценщик проверен на эталонном наборе из 15 реальных сессий, два полных прогона: 96–100 %
оценок по осям — в пределах ±1 от эталона, прогоны расходятся не больше чем на 1 балл, итоговый
уровень совпал у 9 сессий из 15. Планка ±1 при оценках, которые почти все лежат между 2 и 4,
слабая, а оценщик склонен тянуть оценки к середине. Поэтому главное в ревью — цитаты и
конкретные шаги, а не цифры.

## Почему по оси «мало данных», а не оценка?

Лог показывает не всё: вы могли проверить результат в соседнем терминале или обсудить решение
голосом. Когда поведения в логе не видно, честный ответ — «мало данных», и он не превращается в
низкую оценку. Низкая оценка требует положительного доказательства. Подробно — в
[how-it-works.md](how-it-works.md).

## Почему я не вижу баллов?

В тексте ревью баллов нет никогда: человек читает, что менять, а не цифры. В личном HTML-отчёте
баллы по осям и уровень по умолчанию есть. Их нет, если отчёт собран в виде «только динамика»:
`show_scores: false` в `config.json` или в карточке человека, либо `report --trend`. Пересоберите
с `report --scores` или поменяйте настройку — [reports.md](reports.md#баллы-и-уровень).

## Можно сравнить людей в команде?

Нет, ни в каком режиме. Каждый сравнивается только со своим прошлым периодом. Групповой отчёт
показывает оси по людям в алфавитном порядке, без рейтинга и цитат; в карточке человека —
только его собственные одобренные тексты и рекомендации, без сравнения с другими.

## Старые сессии не попали в ретро

Claude Code удаляет свои логи старше `cleanupPeriodDays` дней (по умолчанию 30). Что удалено до
сбора, в ретро не попадёт. Поднимите срок до 90 (`setup` предлагает это сам) и включите хук
SessionEnd: он снимает очищенную копию после каждой сессии, и копия остаётся в workspace после
удаления исходника.

## Сбор не находит сессии Claude Code

Источник `claude-jsonl` с проектом `auto` ищет сессии, открытые из корня проекта. Сессии,
запущенные из подпапки, Claude Code хранит под другим именем, и `auto` их не видит. Открывайте
Claude Code из корня проекта или добавьте ещё один источник `claude-jsonl` с абсолютным путём к
подпапке в `"project"` ([collect.md](collect.md)).

## Работает ли на Windows?

В 0.2 — нет: сбор логов и блокировка файлов на Windows не работают, команды остановятся с
понятной ошибкой. Путь — ручной экспорт сессий и сбор на macOS или Linux.

## Можно получать тексты на английском?

Да: `lang: en` в `config.json` и `address: you` в карточке. Но референсы осей пока только на
русском, и английский текст оценщика на эталонном наборе не проверялся.

## Личный отчёт человека не записался

Перед записью личного файла проверяется, нет ли в нём имён и id других людей workspace. Нашлось —
файл не пишется, в ошибке сказано, что именно найдено. Перепишите одобренное ревью или
рекомендацию без чужого имени и пересоберите отчёт ([reports.md](reports.md)). Заголовок
workspace эта проверка не смотрит: если в нём есть слова из карточек, `report` только
предупреждает (`workspace title contains name tokens of: <id>`), а заголовок уходит в каждый
личный файл. Уберите имена из `workspace.title` в `.retropair/config.json`.

## Отчёт ревьюера тяжёлый

Отчёт ревьюера содержит досье и цитаты всех людей за все периоды: на группе 20 человек за шесть
периодов это около 3 МБ. Он открывается в браузере без сети, но медленнее остальных.

## Куда уходят мои логи?

Никуда, кроме модели через ваш Claude Code: агенты читают очищенные копии в вашей сессии.
Подробно, включая то, чего санитайзер не ловит, — в [privacy.md](privacy.md).

## Как обновить или удалить плагин?

Обновление и удаление — через менеджер плагинов Claude Code (`/plugin`); после обновления
выполните `/reload-plugins` или откройте новую сессию. Состояние пользователя обновление не
трогает: карточки, настройки, история и проектные агенты остаются. При удалении плагина папки
`.retropair/` проектов и `~/.retropair/` тоже остаются; удалите их руками, если они больше
не нужны.

## Где задать вопрос?

Вопросы и идеи — в Discussions репозитория плагина на GitHub, ошибки и предложения — в Issues по
шаблонам ([feedback.md](feedback.md)). Почты нет. Не вкладывайте логи, имена и ключи.
