# Workspace: где sessionretro хранит ваши данные

sessionretro ничего не пишет внутрь самого плагина. Всё, что вы настраиваете и что плагин
собирает, лежит в двух местах:

- **workspace проекта** — папка `.sessionretro/` в корне вашего проекта. Здесь конфиг,
  карточки людей, логи, ревью и отчёты этого проекта;
- **глобальная папка** `~/.sessionretro/` в домашнем каталоге. Здесь реестр всех ваших
  workspace и общие настройки.

Обновление плагина эти папки не трогает: ваши карточки, настройки и история остаются как есть.

## Команды

Все команды запускаются одной точкой входа `sr.py`. Внутри Claude Code путь к плагину
подставляет переменная `${CLAUDE_PLUGIN_ROOT}`:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" --help
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" --version
```

Нужен python 3.10 или новее, сторонние пакеты не нужны.

Команды ищут workspace сами: от текущей папки вверх до первой `.sessionretro/config.json`.
Чтобы указать проект явно, добавьте `--workspace <папка>` в любом месте команды (подходит и
корень проекта, и сама папка `.sessionretro`):

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" people list --workspace ~/work/my-app
```

Коды выхода одинаковые у всех команд: `0` — всё хорошо, `1` — данные не сошлись или не прошли
проверку, `2` — неверный вызов (нет workspace, неизвестный человек, опечатка в аргументах).
Ошибка печатается одной строкой вида `sessionretro: <что упало>: <почему> (<параметры>)`.

### `init` — создать workspace

```bash
cd ~/work/my-app
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" init --mode self
```

Флаги:

| Флаг | Что задаёт | По умолчанию |
|---|---|---|
| `--mode self\|team\|course` | режим: проверяю себя / ревьюер смотрит команду / преподаватель смотрит группу | обязательный |
| `--title "…"` | заголовок workspace, из него же получается id | имя папки проекта |
| `--lang ru\|en` | язык текстов и отчётов | `ru` |
| `--path <папка>` | папка проекта | текущая папка |

Что появится:

- `.sessionretro/config.json` — настройки workspace;
- `.sessionretro/people/_default.yaml` — общие настройки текста для всех карточек;
- `.sessionretro/plugin-state.json` — служебная отметка версии;
- в режиме `self` ещё карточка `.sessionretro/people/me.yaml` (это вы);
- запись о проекте в `~/.sessionretro/workspaces.json`.

Пример для команды:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" init --mode team --title "Команда платформы"
```

```text
workspace создан: /home/user/work/my-app/.sessionretro
id: komanda-platformy · режим: team · язык: ru
```

Кириллица в заголовке транслитерируется в id. Если в папке уже есть workspace, `init` его не
перезаписывает и выходит с кодом `1`. Файл `.gitignore` проекта `init` не меняет (см. раздел
«Что коммитить в git» ниже).

В любом режиме `init` ставит в `config.json` два общих источника без владельца: SpecStory и
Claude Code этого проекта. В team и course, как только вы добавите вторую карточку, `collect`
на них остановится с кодом `1`: удалите их из `sources` или впишите каждому `"person"` —
подробно в [collect.md](collect.md#откуда-берутся-логи).

### `people` — карточки людей

Карточка — это файл `.sessionretro/people/<id>.yaml`: кто человек и как писать ему текст.
id — латиница в нижнем регистре, цифры и дефис (`alex`, `maria-k`, `dev01`).

**Добавить человека:**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" people add alex --name "Alex" --group backend
```

```text
карточка создана: /home/user/work/my-app/.sessionretro/people/alex.yaml
группа backend добавлена в workspace.groups
```

Без `--name` именем станет id, без `--group` — первая группа workspace (после `init` это
`default`). Новая группа сама добавляется в `config.json`. Карточка с таким id уже есть —
код `1`, существующий файл не перезаписывается.

**Посмотреть карточку:**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" people show alex
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" people show alex --json
```

Без флага печатается файл карточки как есть. С `--json` — итоговая карточка, с которой
работает плагин: ваша карточка плюс недостающие настройки текста из `_default.yaml`.

**Список людей:**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" people list
```

```text
alex · Alex · backend
sam · Sam · default
```

`--json` отдаёт те же итоговые карточки массивом.

**Что увидит модель-оценщик:**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" people context alex
```

```text
профиль: backend developer, middle, 4 года; стек: Python, Postgres; инструменты: Claude Code
ограничения: нет прав на прод
обращение: ты; длина: detailed; тон: direct
открывать обобщением: нет; подписывать разделы: нет; приёмы исправления: да
не объяснять: что такое git
границы: нет
ценность: finding; динамика: да
```

Это короткая выжимка карточки (5–8 строк), которую получает оценщик вместе с логами. Пустые
пункты профиля пропускаются. Имя и оформление текста (`channel`, `template`, `prefix`) в
выжимку не попадают. `--json` отдаёт те же строки массивом.

Неизвестный id или id в неверном формате — код `2`.

### `doctor` — проверить, всё ли на месте

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" doctor
```

```text
workspace: /home/user/work/my-app
mode: team
people: 2
python: 3.12.4
specstory: 2.6.0 (SpecStory)
hook_enabled: да
cleanup_period_days: не задан
registry_count: 1
last_run_at: нет
last_collect_at: нет
plugin_version: 0.1.0
```

| Строка | Что значит |
|---|---|
| `workspace` | найденный проект или «не найден» |
| `mode`, `people` | режим workspace и число карточек |
| `python` | версия интерпретатора |
| `specstory` | версия SpecStory CLI или «не найден» (ждёт ответа до 5 секунд) |
| `hook_enabled` | включён ли автоснапшот логов по концу сессии Claude Code |
| `cleanup_period_days` | сколько дней Claude Code хранит логи сессий (`~/.claude/settings.json`) |
| `registry_count` | сколько workspace в глобальном реестре |
| `last_run_at`, `last_collect_at` | когда была последняя оценка и последний сбор логов |
| `plugin_version` | версия плагина |

`doctor` не падает, если чего-то нет: он честно пишет «не найден» или «не задан». Код `1` —
только если какой-то JSON-файл битый (конфиг, реестр, `~/.claude/settings.json`) или карточка
не читается. `--json` печатает то же одним объектом.

## Что лежит в `.sessionretro/`

```text
.sessionretro/
├── config.json              # настройки workspace: режим, язык, группы, источники логов, модели
├── people/
│   ├── _default.yaml        # общие настройки текста для всех карточек
│   └── <id>.yaml            # карточка человека (в режиме self — одна, me.yaml)
├── logs/<id>/…              # очищенные копии логов сессий (сырые логи не хранятся)
├── logs-index.json          # перечень собранных сессий
├── runs/process-reviews.json    # история оценок по периодам
├── runs/pending/            # промежуточные файлы текущего прогона
├── reviews/<id>/…           # тексты ревью: черновик → одобрено
├── reports/                 # HTML-отчёты
├── templates/feedback.md    # ваш шаблон текста (необязательно)
├── improvements/            # ваши предложения по улучшению плагина (необязательно)
├── agents.json              # отпечатки проектных агентов: правили вы их или нет
├── collect.log              # журнал фонового сбора (пишет хук)
├── collect.lock             # замок сбора
└── plugin-state.json        # служебная отметка: версия формата и плагина
```

`agents.json` появляется, когда `setup` или `agents write` кладут проектных агентов в
`.claude/agents/`. В нём по каждой роли — отпечаток тела агента и версия плагина. По нему плагин
понимает, правили вы файл агента или нет: не правили — после обновления плагина файл обновится
сам, правили — останется как есть. Подробно — в [customize.md](customize.md), раздел «После
обновления плагина». Файл можно коммитить вместе с `.claude/agents/`.

Сразу после `init` есть только `config.json`, `people/` и `plugin-state.json`; остальное
появляется, когда вы собираете логи, запускаете оценку и строите отчёты.

## Что лежит в `~/.sessionretro/`

```text
~/.sessionretro/
├── workspaces.json          # реестр workspace: id, путь, заголовок, режим, группы, даты
├── config.json              # ваши общие настройки по умолчанию (модели, язык)
├── reports/index.html       # страница со всеми workspace
├── clones/                  # клоны git-репозиториев с логами (режимы team и course)
└── plugin-state.json        # служебная отметка
```

Реестр нужен, чтобы видеть все проекты с одной страницы. Его ведут команды плагина
(`init` добавляет запись), править файл руками не нужно.

Посмотреть реестр и убрать лишнее (например, удалённую песочницу) — команда `workspaces`.
`list` показывает id, путь, заголовок и режим и помечает «папки нет», если у записи пропал
`.sessionretro/config.json`; `remove <id>` убирает одну запись, `remove --missing` — все
помеченные. Файлы проектов не трогаются, страница workspaces обновится при следующем
`report --index`:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" workspaces list
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" workspaces remove --missing
```

## Карточка человека

```yaml
id: alex
name: "Alex"
group: backend
profile:
  role: backend developer
  grade: middle
  years: 4
  stack: Python, Postgres
  tools: Claude Code
  constraints: нет прав на прод
feedback:
  address: вы
  skip_basics:
    - что такое git
sources:
consent:
  logs: true
  date: 2026-09-01
```

- `id` — совпадает с именем файла; `name` — имя для текста; `group` — группа из
  `config.json`.
- `profile` — роль, грейд, опыт в годах, стек, инструменты, ограничения. Всё необязательно,
  но чем полнее, тем точнее советы: оценщик не станет предлагать то, что человеку недоступно.
- `feedback` — как писать текст этому человеку (ниже). Указывайте только то, что отличается
  от `_default.yaml`, остальное подставится само.
- `sources` — дополнительные источники логов этого человека, например папка
  (`type: dir`, `path: …`).
- `consent` — согласие на сбор логов и его дата (для режимов team и course). `logs: false`
  блокирует и сбор, и оценку: источники человека не читаются, ранее собранные снапшоты
  исключаются из пачек (подробнее — в [сборе логов](collect.md)).

### Настройки текста `feedback`

Одиннадцать параметров задают содержание и манеру текста — их видит оценщик. Ещё три
отвечают только за оформление, и один необязательный — за вид личного отчёта; эти четыре
оценщику не подаются.

| Параметр | Значения | Что меняет |
|---|---|---|
| `address` | `ты` · `вы` · `you` | как обращаться к человеку; `you` — для текста на английском |
| `length` | `short` · `detailed` | объём текста: коротко или развёрнуто |
| `tone` | `direct` · `supportive` | тон: прямой или поддерживающий |
| `opening_summary` | `true` · `false` | начинать ли текст обобщением простым языком |
| `mark_sections` | `true` · `false` | подписывать ли части «что менять» и «на чём стоит» |
| `practices` | `true` · `false` | давать ли приёмы «как исправить» по слабым местам |
| `skip_basics` | список | что человек и так знает — это не объясняем |
| `boundaries` | список | жёсткие запреты: например, не переносить советы на рабочий стек или требования комплаенса |
| `avoid` | список | чего не делать в тексте (сравнений, сленга, эмодзи…) |
| `value_focus` | `finding` · `full` | в чём ценность текста: в находках, которых человек сам не видел, или в полном проходе по всем осям |
| `show_dynamics` | `true` · `false` | показывать ли изменения с прошлого периода |
| `channel` | `file` · `telegram` · `slack` · `email` | куда пойдёт текст; влияет на переносы строк (оформление) |
| `template` | `default` · `workspace` · имя файла | какой шаблон текста взять (оформление) |
| `prefix` | строка | что поставить перед текстом, например приветствие (оформление) |
| `show_scores` | `true` · `false` · нет строки | вид личного отчёта этого человека: с баллами и уровнем или только динамика ↑ → ↓ ◇; нет строки — как `show_scores` в `config.json`; флаг `report --scores`/`--trend` сильнее ([reports.md](reports.md#баллы-и-уровень)) |

Списки пишутся по пункту на строку:

```yaml
feedback:
  boundaries:
    - не предлагать облачные сервисы
    - не трогать прод
```

Чтобы поменять настройку для всех сразу, правьте `people/_default.yaml`. Чтобы для одного
человека — раскомментируйте блок `feedback:` в его карточке и оставьте нужные строки.

Карточка проверяется при каждом чтении. Неизвестное значение (например, `tone: soft`) или
id, не совпадающий с именем файла, — ошибка с кодом `1` и точным указанием поля.

## Что коммитить в git

Workspace задуман как «папка фидбэка в репозитории»: настройки, карточки, история оценок и
тексты ревью хорошо хранить вместе с проектом. Не стоит коммитить тяжёлое и промежуточное:

```gitignore
.sessionretro/logs/
.sessionretro/runs/pending/
.sessionretro/reports/
.sessionretro/collect.log
.sessionretro/collect.lock
```

- `logs/` — копии логов сессий. Они очищены от секретов и путей, но это всё равно переписка
  с агентом;
- `runs/pending/` — черновые файлы незавершённого прогона;
- `reports/` — HTML, который всегда можно пересобрать;
- `collect.log` и `collect.lock` — журнал фонового сбора и его замок, служебные файлы машины.

`~/.sessionretro/` — ваша личная папка, в репозиторий проекта она не попадает.

Карточки в режимах team и course содержат имена и профиль людей. Прежде чем коммитить их в
общий репозиторий, убедитесь, что люди с этим согласны. Что ещё остаётся у вас, что видят
модели и чего не ловит санитайзер — в [privacy.md](privacy.md).
