## [0.1.14] — 2026-09-28

### Fixed

- Групповой отчёт строится только из одобренных прогонов: теплокарта, «последний прогон каждого», уровни, распределение, плитки, карточка человека и даты в шапке — без черновиков, которых адресат не получал. Человек без одобренных прогонов в строках не появляется, он учтён в плитке «ещё нет одобренных: N». Отчёт ревьюера не изменился.

### Changed

- Документация: README EN/RU переписан подробно — полный цикл по шагам, восемь осей, как ставится оценка, петля рекомендаций и вердиктов, персонализация по полям карточки человека, что видит ревьюер и что адресат, сбор логов, приватность, настройка, стоимость и качество, FAQ.
- Документация: галерея скриншотов отчётов RU/EN (в том числе тёмная тема) вместо прежних скриншотов группового и личного отчёта; английская страница отчётов `docs/en/reports.md`.
- Документация: на схеме «как это работает» — петля предложений правок карточки (предложение → ревьюер подтверждает или отклоняет → карточка человека).
- Шаблоны карточки: комментарий к `channel` уточнён — пока только метка, текст не меняет.
- Уточнения страниц документации по сверке с кодом 0.1.13 (reports, review, customize, privacy, faq, setup, workspace, axes): баллы в личном отчёте видны по умолчанию, стоимость, `approve` и предложения правок карточки.

## [0.1.13] — 2026-09-28

### Added

- Предложения правок карточки человека: `people suggestions [--refresh] [--all]`, `people apply`, `people reject --reason`; файл `people/<id>.suggestions.json`, блок в `reviewer.html`, строка `card_suggestions_pending` в `doctor`; судья v16 с необязательным `card_suggestions` (только профиль); карточка меняется только командой, баллы — никогда.
- Групповой отчёт: карточка человека по клику — графики, «Фидбэк по периодам» с выбором периода и вкладкой «все», рекомендации с историей вердиктов; без баллов и уровней. Включена по умолчанию, выключается `--no-details` или `report.group_details: false` в конфиге.
- Личный отчёт: история вердиктов под каждой рекомендацией — только одобренные прогоны, от старого периода к новому; без вердиктов — «ещё не проверялась».
- Документация: анимированные схемы «как это работает» (RU/EN) в README и `how-it-works`; английская документация — 7 новых страниц (axes, collect, faq, feedback, review, setup, workspace).

### Changed

- Личный отчёт строится как карточка ревьюера без служебных блоков (пояснения судьи, доказательства, черновики). Баллы и уровни в нём видны по умолчанию (вид scores); вид только с динамикой по осям — `--trend` или `feedback.show_scores: false` в карточке человека, `--scores` включает баллы принудительно (`--show-scores`/`--hide-scores` по-прежнему работают). Сводка `review` в режиме self следует тому же ключу; в тексте ревью баллов нет.
- Групповой отчёт без `--anon` не пишется, если в нём встречается слово из `sanitize.names`: старый файл удаляется, код 1.
- Таблица в тексте ревью на узком экране прокручивается внутри себя, а не вся страница.
- Пояснения вердиктов и стек агентов для адресата очищаются при сборке (логин ОС, почта, телефоны, пути машины); с `--anon` групповой отчёт помечен плашкой «обезличено».

## [0.1.11] — 2026-09-28

### Fixed

- A03: `plugin-state.json` переходит на новую версию плагина — `pluginVersion` и `lastSync` обновляются при любой команде `sr.py`.
- A05: `turns_total` прогона у выросшей сессии считается по хвосту (новые ходы после прошлой оценки), расхождение с числом ходов у судьи и сессия вне индекса — строка в warnings; начало периода не раньше конца предыдущего прогона человека.
- A11: подписи периодов — внутри карточки, без шума про отозванные ревью, в счётчике сессий — только оценённые; метка прогона на оси X — номер периода без даты запуска.
- A14: предупреждение «дубль ключа» выводится один раз — известные дубли запоминаются, дальше только счётчик, без повторного разбора.
- A16: вердикт по прошлой рекомендации выносится только по логам после её выдачи (время прогона или `approve`); логи периода старше выдачи получают вердикт `not_applicable_yet` («Рано судить»), рекомендация остаётся открытой; `open-recs` отдаёт `issued_at` и `evaluable`, `append` заменяет вердикт по логам старше выдачи со строкой в warnings; промпты судьи v15 и коллектора v5.

## [0.1.9] — 2026-09-28

### Fixed

- A01: санитайзер вырезает пароль и в выводе инструмента — метку сразу после экранированного `\n` в выведенном исходнике и колонку пароля под заголовком CSV или таблицы.
- A12: `check-collector` сам чинит цитаты коллектора при однозначном сдвиге хода и склейке кусков одной реплики человека; после двух перезапусков коллектора несверенные цитаты отбрасываются (`--drop-invalid`) вместо остановки прогона, ось без наблюдений уходит в `axes_unobserved` с причиной `quote_unverified`; промпт судьи v14.
- A13: многозначные флаги `--excluded`, `--sessions` (`mark-logs`) и `--skipped` (`append`) при повторе накапливаются, а не перетирают друг друга; одна ссылка дважды — код 2, ничего не записано.
- A15: `/sessionretro:review` в начале прогона выполняет `agents sync` — непроправленные проектные агенты обновляются до промпта текущей версии плагина, правленые не трогаются, а о них выводится напоминание.
- Уточнения документации и мелкие исправления по находкам e2e, в том числе причины «данных нет» в отчёте совпадают с перечнем схемы судьи.

## [0.1.0] — 2026-09-28

- Каркас плагина: CLI `sr.py` (`init`, `people`, `doctor`), схемы, шаблоны.

- Сбор логов: `sr.py collect` (санитайзированные снимки сессий Claude Code, SpecStory, папок и git в `.sessionretro/logs/`, сводка), `sr.py inventory` (перечень сессий со статусами), `sr.py normalize` (разбор одного лога), хук SessionEnd для фонового сбора, скилл `collect`, инструкции по связкам среды и агента, страница `docs/ru/collect.md`.

- Оценка: промпты коллектора (v3), судьи (v13) и критика, референсы осей, антипаттернов, приёмов, контракта текста и датасета формулировок, схемы выхода коллектора (v2) и судьи (v3), имена в `i18n.json`, шаблоны текста на двух языках и болванки проектных агентов.

- Движок оценки и скилл `review`: трекер прогонов v2 (`append`, `validate`, `retract`, `compare`, `open-recs`, `mark-logs`, `verify`), уровень по формуле (`level`), нарезка на пачки (`batches`), проверка выхода коллектора (`check-collector`), текст ревью по шаблону с проверкой запретов (`render-review`), одобрение черновика (`approve`), самопроверка (`self-test`); страницы `docs/ru/how-it-works.md` и `docs/ru/review.md`.

- Отчёты `sr.py report` и скилл `/sessionretro:report`: отчёт ревьюера, групповой (team, course), личные файлы с проверкой на чужие имена, страница всех workspace, обезличивание `--anon`; строка `reports_built_at` в `doctor`; страница `docs/ru/reports.md`.

- Настройка `/sessionretro:setup`: диалог из 11 вопросов и `sr.py setup-apply --answers` / `setup-state`; проектные агенты с моделью и effort (`agents write|check`); предложения авторам плагина без автоотправки (`improve add|list|pack|sent|sync`); новые строки `doctor`; страницы `docs/ru/setup.md`, `customize.md`, `feedback.md`.

- Приватность: санитайзер вычищает логин в домашних путях с любыми символами (кириллица, пробел в логине Windows), в экранированных и смешанных Windows-путях и в WSL; `_` — граница слова для имён и хэндлов, в том числе в `--anon`; заголовок workspace не считается чужим именем в личных отчётах, но `report` предупреждает, если в нём есть слова из карточек; хук SessionEnd запускает сбор только в workspace из реестра `~/.sessionretro/workspaces.json`.

- Демо-workspace `demo/`: обезличенная учебная группа с вымышленными именами — 15 человек, пять периодов, одобренные тексты; команда сборки отчётов в `demo/README.md`.

- Документация: README на английском и русском, `ROADMAP.md`, индекс `docs/README.md`, страницы `docs/ru/privacy.md` и `docs/ru/faq.md`, английские страницы `docs/en/how-it-works.md`, `privacy.md`, `customize.md`.
