# Отчёты ретро

Скилл собирает HTML-отчёты из уже проведённых оценок и говорит пользователю, какой файл
открыть. Отчёты ничего не оценивают и никуда не отправляются: это локальные файлы, которые
открываются в браузере без сети.

## Когда запускать

- После оценки периода (скилл `review`), чтобы увидеть результат и динамику.
- После того как ревьюер одобрил текст ревью: в личный отчёт попадают только одобренные тексты.
- Когда пользователь просит показать или обновить отчёты, динамику, страницу всех workspace.

Если оценок ещё не было (команда ответит «нет трекера прогонов»), отчёт собирать не из чего:
предложи сначала провести оценку периода скиллом `review`.

## Аргументы скилла

| Аргумент | Что делает |
|---|---|
| `--no-ask` | ни одного вопроса пользователю (для `claude -p` и фоновых запусков): вид личных отчётов берётся из конфига и карточек |

## Команда

Все пути в кавычках. `${CLAUDE_PLUGIN_ROOT}` — корень плагина; если переменная не
подставилась, корень плагина — два уровня выше этого файла.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" report
```

Без флагов собирается всё, что уместно режиму workspace:

- `self` — отчёт ревьюера (ревьюер здесь сам пользователь), личный отчёт и страница всех
  workspace;
- `team` и `course` — ещё и групповой отчёт.

Частые флаги (полный список — `rp.py report --help`):

| Флаг | Когда нужен |
|---|---|
| `--workspace "<папка проекта>"` | команда запущена не из папки проекта |
| `--personal <id>` / `--all-personal` | только личный отчёт одного человека / всех |
| `--group`, `--reviewer`, `--index` | только выбранные файлы |
| `--no-details` | групповой отчёт без карточки человека — только цифры, для показа группе |
| `--anon` | отчёт покажут посторонним: демо, скриншот, пример в чате |
| `--scores` / `--trend` | вид личных отчётов на этот запуск: с баллами и уровнем / только динамика (см. ниже) |
| `--lang ru\|en` | язык отчёта, если нужен не тот, что в конфиге |
| `--out-dir "<папка>"` | собрать в другую папку, не трогая основную |

## Баллы или динамика

Личный отчёт собирается в одном из двух видов:

- **Баллы** (`--scores`) — графики «Оси во времени» с баллами 0–4 и уровень по последнему
  прогону, как в карточке ревьюера;
- **Только динамика** (`--trend`) — та же карточка, но вместо баллов переходы между
  периодами: ↑ лучше, → ровно, ↓ ниже, ◇ нет данных; баллов и уровня в файле нет вовсе.

Когда запуск собирает личные отчёты (`--personal`, `--all-personal` или сборка без флагов
целей) и `--no-ask` не передан, до команды задай пользователю один вопрос — один раз на весь
запуск, не по человеку: «Баллы или только динамика?» Варианты: «Баллы» → добавь `--scores`;
«Только динамика» → добавь `--trend`; «Как настроено» → без флага. Флаг действует на всех
людей этого запуска и сильнее настроек.

Без флага вид решают настройки. Приоритет: флаг запуска > `feedback.show_scores` карточки >
`config.show_scores`. Карточка `people/<id>.yaml` может задать вид одному человеку
(`feedback.show_scores: false` — ему только динамика); в конфиге по умолчанию
`"show_scores": true` (баллы).

При `--no-ask` не спрашивай и флаг вида не добавляй: вид берётся из `config.show_scores` и
`feedback.show_scores` карточек.

Прежние имена флагов работают: `--show-scores` = `--scores`, `--hide-scores` = `--trend`.
Два флага вида сразу — ошибка вызова, код `2`. «Как видит адресат» в отчёте ревьюера
показывает ровно тот вид, в котором соберётся личный файл человека.

## Что сказать пользователю

Команда печатает по строке на файл: `путь · размер`. Перескажи, что открыть:

- `reports/reviewer.html` — рабочий файл ревьюера: всё, включая черновики, досье и
  доказательства. Его не пересылают.
- `reports/group.html` (только team и course) — один интерфейс на группу: оси по людям в
  алфавитном порядке, по клику на человека — его карточка: оси во времени, одобренные тексты
  ревью по периодам (вкладка «все» — подряд) и рекомендации с вердиктами; селектор периода
  подсвечивает рекомендации периода. Не для рассылки: в файле данные всех участников. С
  `--no-details` или `"report": {"group_details": false}` в конфиге — только цифры.
- `reports/personal/<id>.html` — личный файл человека: та же карточка, что у ревьюера, без
  служебного (пояснений судьи, главного по прогону, доказательств, досье, черновиков): оси во
  времени (с баллами или только динамика — по виду), агенты и модели, одобренные тексты ревью
  по периодам, рекомендации с вердиктами. Именно его можно отправить адресату.
- `~/.retropair/reports/index.html` — страница со всеми workspace пользователя.

Строки `предупреждение: …` в выводе (ревью без прогона, люди без прогонов, уровень взят из
запасного поля) перескажи коротко: отчёт собран, но на них стоит взглянуть.

В режиме `self` группового отчёта нет: там один человек. Флаг `--group` в `self` пишет
«в режиме self групповой отчёт не собирается»; если других целей не было, код выхода `1`.

## Если сработал гейт чужих имён (код 1)

Перед записью личного файла команда ищет в нём имена и id других людей workspace и имена из
`sanitize.names` в конфиге. Нашлись — файл не пишется, старый удаляется, в выводе строка
`retropair: чужие токены в <путь>: …`, код `1`; остальные файлы собираются. Групповой
отчёт (`group.html`) проверяется так же, но только на `sanitize.names`: имена участников в нём
законны.

Что делать: покажи пользователю найденные токены и файл ревью этого человека
(`.retropair/reviews/<id>/…`). Обычно чужое имя попало в отправляемый блок одобренного
ревью или в текст рекомендации. Предложи убрать его из текста и пересобрать отчёт. Не
обходи гейт и не правь HTML руками.

## Перед показом посторонним — `--anon`

Если отчёт увидит кто-то кроме ревьюера и адресата (демо, скриншот для статьи, пример в
issue), собери его с `--anon` в отдельную папку:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rp.py" report --anon --out-dir "/tmp/retropair-demo"
```

В обезличенных файлах коды `p01…` вместо id, вымышленные имена, без e-mail, ссылок на
профили, `@хэндлов` и домашних путей. Личные файлы называются по коду: `personal/p01.html`.
Если id людей сами похожи на `p01`, коды получат другую букву (`x01…`).
Страница всех workspace не обезличивается — она только для самого пользователя.

## Коды выхода

`0` — всё собрано. `1` — сработал гейт, нет или битый трекер оценок, нет ни одного прогона,
у выбранного человека нет прогонов, групповой отчёт в `self` как единственная цель.
`2` — неверный вызов: нет workspace, неизвестный id в `--personal`, `--personal` вместе с
`--all-personal`, два флага вида сразу (`--scores` и `--trend`). Текст ошибки перескажи как есть: в нём сказано, что упало и где.

Подробно для пользователя — страница `docs/ru/reports.md` плагина.

Упёрся в ограничение плагина — протокол предложений: `${CLAUDE_PLUGIN_ROOT}/references/improvements-protocol.md`.
