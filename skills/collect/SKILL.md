# collect — собрать логи сессий

Скилл без диалога: ничего не спрашивай, запусти сбор и объясни результат. Сбор безопасен для
повтора: исходники не меняются, неизменные снимки не переписываются.

## Шаг 1. Запустить сбор

Из корня проекта пользователя (или из любой его подпапки):

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" collect
```

Если `${CLAUDE_PLUGIN_ROOT}` не подставился литералом, корень плагина — папка на два уровня выше
этого SKILL.md (`skills/collect/SKILL.md` → корень). Путь всегда в кавычках: в нём могут быть
пробелы.

Флаги, если пользователь просит:

- `--provider <имя>` — какого агента выгружает `specstory sync` (повторяемый: `claude`, `codex`,
  `cursoride`, `antigravity`…); без флага берётся `hook.providers` из конфига, иначе `claude`;
- `--json` — сводка одним JSON-объектом (для разбора, пользователю не показывать сырым);
- `--replace <имя снимка>` — перезаписать этот снимок в `.sessionretro/logs/<id>/`, даже если
  новый короче лежащего (повторяемый). Нужен, когда исходник почистили руками и вырезали целый
  ход: без флага защита от усыхания оставит вырезанное в копии;
- `--workspace <папка>` — если проект не текущая папка.

Коды выхода: `0` — сбор прошёл (даже с предупреждениями), `1` — данные не сошлись (битый шаблон
в `sanitize.extra_patterns`, источник без `person` при нескольких карточках, ошибка git), `2` —
неверный вызов, в том числе «workspace не найден». Текст ошибки — одна строка
`sessionretro: …`; перескажи её своими словами и назови, что поправить.

**Workspace не найден** (код `2`, «нет .sessionretro/config.json ни в папке, ни выше»): сбор не
повторяй, предложи сначала настроить плагин командой `/sessionretro:setup`.

## Шаг 2. Показать сводку человеческим языком

Не копируй вывод целиком — перескажи:

- сколько сессий в инвентаре и сколько из них новых, выросших, без изменений, дублей,
  пропавших, исключённых. «Новая» значит «ещё не оценена»: запись остаётся новой при повторных
  сборах, пока её не разберёт оценка; «выросла» — сессию уже оценивали, а в ней появились новые
  ходы; «пропала» — снимок удалили из `.sessionretro/logs/` руками;
- что вычистил санитайзер: по файлам, какие правила сработали и сколько имён заменено
  (`home_path` — логин в домашних путях, `code_secret`/`env_secret` — пароли и токены
  в присваиваниях и т.д.). Если срабатываний нет, так и скажи;
- строку `specstory:` — прошла ли выгрузка SpecStory (`ок`, «не найден, sync пропущен», версия
  ниже 2.6.0, код ошибки);
- дату последнего снимка (`last_snapshot_at`).

## Шаг 3. Объяснить `*.orig` и слаг-файлы

- **`*.orig`** — сырые копии, которые остаются после ручной чистки лога (исходник до правки).
  Плагин их не пишет и не берёт в сбор, только считает. Если счётчик не ноль, предупреди: такие
  файлы не коммитить и не отдавать другим — в них то, что вычищали.
- **Слаг-файлы SpecStory** — выгрузки вида `2026-09-01_10-00-00Z-fix-login-bug.md`: SpecStory
  называет файл по началу первого промпта. Они берутся в сбор как обычные, но снимок в
  `.sessionretro/logs/` называется по ключу сессии, так что текст промпта в имя снимка не
  попадает. Счётчик в сводке — просто для сведения.
- Файлы `context-report*` тоже не берутся, только считаются.

## Шаг 4. Предупреждения источников

Строки из блока «предупреждения» объясни по одной:

- «папки нет, источник пропущен» — источник из `config.json` указывает на несуществующую папку
  (например, SpecStory ещё не ставили, или Claude Code не запускали в этом проекте). Не ошибка;
- «тип … не поддерживается в 0.1» — источник `codex-jsonl`/`cursor-jsonl`; такие логи собираются
  через SpecStory;
- «исходник без ходов / не разобран, пропущен» — файл не похож на лог сессии;
- «снапшот … не перезаписан: в новом N ходов, меньше…» — исходник укоротился, лежащий снимок
  сохранён. Объясни оба случая: если исходник укоротили намеренно (вычистили приватное),
  сбор нужно повторить с `--replace <имя снимка>` — готовая команда в конце строки, — иначе
  вырезанное останется в копии; если файл перезаписала другая программа, данные не потеряны;
- «дубль ключа …» — одна и та же сессия пришла из двух источников, взят более полный файл;
- «под ключом … другая сессия» — две разные сессии с одинаковым ключом (например, ручные
  экспорты с одинаковым началом): обе сохранены, вторая — с суффиксом в имени снимка;
- «workspace не в реестре …» — `last_collect_at` не записан; лечится повторной настройкой через
  `/sessionretro:setup`.

Если пользователь просит почистить логи от имени или названия: пусть впишет его в
`sanitize.names` конфига, затем повтори сбор — все снимки перечистятся, в том числе те, чьих
исходников уже нет.

## Шаг 5. Хук

Автоматический сбор по концу каждой сессии Claude Code делает хук SessionEnd: он запускает этот
же сбор в фоне, а вывод пишет в `.sessionretro/collect.log`. Включается и выключается в
`/sessionretro:setup` (в конфиге это `hook.enabled`). Если пользователь собирает руками и хук
выключен, один раз упомяни, что его можно включить там.

Строка «сбор уже идёт» в `collect.log` значит, что фоновый сбор не дождался соседнего за 120
секунд. Это не ошибка: соседний сбор возьмёт и эту сессию, а если не успел — её возьмёт
следующий.
