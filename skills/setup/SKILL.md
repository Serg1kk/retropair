# setup — настроить sessionretro в проекте

Скилл ведёт онбординг диалогом: узнаёт текущее состояние, задаёт до 11 вопросов по одному,
собирает ответы в один JSON и применяет их одной командой `setup-apply`. Сам скилл файлов не
пишет: всё пишет `sr.py`. Повторный запуск показывает текущие значения и меняет только выбранное.

Формулировки, варианты ответов и JSON каждого вопроса — [references/questions.md](references/questions.md).
Прочитай его целиком перед первым вопросом.

## Шаг 0. Корень плагина

Каждая команда вызывается так: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" <команда> …`.
Если в пути остался литерал `${CLAUDE_PLUGIN_ROOT}` (хост его не подставил), корень плагина —
папка два уровня выше этого `SKILL.md` (`skills/setup/SKILL.md` → корень): подставь её абсолютный
путь, в команде — в кавычках (в пути бывают пробелы). В файлы пользователя абсолютные пути плагина
не пишутся.

Коды выхода у всех команд: `0` ок, `1` данные или проверка, `2` неверный вызов. Ошибка — одна
строка в stderr: что упало, почему, с какими параметрами. Перескажи её и назови, что поправить;
не продолжай на значениях по умолчанию.

## Шаг 1. Состояние

Из папки проекта пользователя:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" setup-state --json
```

Настраивается корень git-репозитория от текущей папки (не git — сама папка). Пользователь назвал
другой проект — добавь глобальный флаг перед командой: `sr.py" --workspace "<папка проекта>" setup-state --json`,
и ту же папку передай ключом `path` в ответах.

- `"workspace": null` → **первый запуск**: вопросы 1–11 по порядку (раздел «Первый запуск»).
- `workspace` — объект → **повторный запуск** (раздел «Повторный запуск»). Его поля — текущие
  значения в формате ответов `setup-apply`.
- `found` — находки окружения для условий пропуска и рекомендаций: `specstory_dir` (есть ли
  `.specstory/history`), `claude_projects_dir` и `jsonl_files` (логи Claude Code этого проекта),
  `specstory_version` (`null` — не установлен), `found.cleanup_period_days` — сколько дней
  Claude Code хранит логи (`null` — не задан, по умолчанию 30).

## Правила диалога

- **Один вопрос — один вызов AskUserQuestion.** Вопросы не склеиваются и не задаются текстом.
- **2–4 варианта**, первый — рекомендуемый (первый запуск) или текущий (повторный), с пометкой
  `(Recommended)` в конце метки.
- **Одна фраза «зачем»** у каждого вопроса — в тексте вопроса после самого вопроса (готовые — в
  `references/questions.md`, строка «Зачем:»).
- **Свой ввод — через Other.** Id и имена людей, пути к логам, окна дат, свой набор моделей
  выбрать нельзя: их пользователь вписывает в поле Other, которое AskUserQuestion добавляет сам.
  Значения не придумываются; не разобрался в ответе — переспроси тот же вопрос один раз, показав формат.
- **Ответы копятся в памяти** до шага «Применение»: до него ничего не пишется.
- Пользователь отказался отвечать на вопрос → ключ не передаётся (на первом запуске останется
  значение плагина по умолчанию; назови его в итоговой таблице).
- Без вопроса: `lang` — язык разговора с пользователем (`ru` или `en`), `title` — не передаётся
  (будет имя папки проекта), пока пользователь сам не назвал проект иначе; `path` — только если
  настраивается не текущий проект.
- Режим `course` в разговоре — «учебная группа»: разбирает преподаватель, людей в ней — участники группы.

## Первый запуск

Вопросы по порядку; пропуск — только по условию в вопросе.

### Вопрос 1. Режим → `mode`

self / team / course (учебная группа, преподаватель). Обязателен на первом запуске: без `mode`
`setup-apply` ответит кодом 2.

### Вопрос 2. Участники → `people`

Только team и course. В self не задаётся: карточку `me` создаёт `setup-apply`. Список людей —
через Other, строкой `id; Имя; группа; логи` на человека; разбор строки и форма источников —
в `references/questions.md`.

### Вопрос 3. Источники workspace → `sources`

Варианты строятся по `found`: сколько сессий Claude Code найдено, есть ли `.specstory/history`.
В team и course рекомендуемое — `"sources": []`: логи каждого человека идут из его `sources`
(вопрос 2), а источник без владельца при нескольких карточках сбор не примет.

### Вопрос 4. SpecStory (без ключа)

Пропускается, если `found.specstory_version` — версия 2.6.0 или выше. Иначе предложи установку и
покажи команды из `references/questions.md`; запускает их пользователь сам (скилл ничего не ставит).

### Вопрос 5. Хук → `hook`

`true` — сбор в фоне по концу каждой сессии Claude Code (хук SessionEnd), `false` — вручную.

### Вопрос 6. Модели и effort → `models`

Пресеты с пояснением цены и качества: «Сбалансировано (Recommended)» — коллектор sonnet/medium,
судья opus/high, критик sonnet/medium; «Экономно» — haiku/low, sonnet/medium, haiku/low;
«Максимум» — opus/high, opus/max, opus/medium; «Свой» — через Other. JSON каждого пресета — в
`references/questions.md`. По `models` `setup-apply` пишет проектных агентов
`.claude/agents/sessionretro-*.md`.

### Вопрос 7. Баллы → `show_scores`

Рекомендуемое — `true`: личный отчёт с баллами и уровнем, как карточка ревьюера; `false` —
только динамика ↑ → ↓ ◇.

### Вопрос 8. Периоды → `period`

`run` (по дате запуска, рекомендуемое), `dates` с окнами из Other, `labels` (в 0.1 скилл `review`
метку не спрашивает, прогоны пишутся без метки; своё имя периода — через окна `dates`).

### Вопрос 9. Шаблон текста → `template`

`default` — шаблон плагина; `workspace` — копия в `.sessionretro/templates/feedback.md` для правки.
Выбор ложится и в `feedback.template` файла `people/_default.yaml` — по нему строится текст.

### Вопрос 10. Хранение логов → `cleanup_period_days` (`write` только после «да»)

Пропускается, если `found.cleanup_period_days` уже 90 или больше. Ответ — объект с полями
`value` и `write`: `write: true` — только если пользователь явно ответил «да» (тогда `setup-apply` пишет `~/.claude/settings.json`); иначе `write: false`,
и в выводе будет совет.

### Вопрос 11. .gitignore → `gitignore`

`true` — дописать в `.gitignore` проекта недостающие строки для логов, черновиков и отчётов.

## Повторный запуск

1. Покажи текущие значения таблицей из `setup-state --json`: режим, люди (id и группы), источники,
   хук, модели по ролям, баллы, режим периодов, шаблон, `.gitignore`, `found.cleanup_period_days`.
2. Один AskUserQuestion с `multiSelect: true`, вопрос «Что поменять?», четыре варианта:
   - «Режим, люди и источники» — вопросы 1–4;
   - «Хук, cleanup, gitignore» — вопросы 5, 10, 11;
   - «Модели» — вопрос 6;
   - «Баллы, периоды, шаблон» — вопросы 7–9.
3. Задай только вопросы выбранных блоков, по одному, в порядке номеров. Первым вариантом каждого —
   текущее значение с `(Recommended)`. Условия пропуска те же.
4. В ответы идут только ключи, значение которых изменилось. Ничего не выбрано или ничего не
   изменилось — скажи «ничего не меняем», `setup-apply` не зови, покажи `doctor`.

Блоки: люди и источники · хук, cleanup, gitignore · модели · баллы, периоды, шаблон.
Существующие карточки людей `setup-apply` не перезаписывает: имя или группу человека правят в
файле `.sessionretro/people/<id>.yaml`.

## Применение

Перед вызовом покажи итог ответов короткой таблицей «вопрос → значение». Затем **один** вызов с
ответами в heredoc (кавычки у `'EOF'` обязательны: шелл не трогает текст внутри):

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" setup-apply --answers - <<'EOF'
{
  "mode": "team",
  "lang": "ru",
  "people": [
    {"id": "alex", "name": "Alex", "group": "team-a",
     "sources": [{"type": "git", "url": "https://example.com/team/alex-logs.git"}]},
    {"id": "maria", "name": "Maria", "group": "team-a"}
  ],
  "sources": [],
  "hook": true,
  "models": {"collector": {"model": "sonnet", "effort": "medium"},
             "judge": {"model": "opus", "effort": "high"},
             "critic": {"model": "sonnet", "effort": "medium"}},
  "show_scores": true,
  "period": {"mode": "run"},
  "template": "default",
  "cleanup_period_days": {"value": 90, "write": false},
  "gitignore": true
}
EOF
```

Настраивается не текущий проект или пользователь назвал его сам — добавь в ответы:

```json
{"path": "/home/user/other-project", "title": "Other project"}
```

Что делать с результатом:

- **Код 0.** Покажи вывод целиком: строки `создал: …`, `изменил: …`, `без изменений: …`, `совет: …`.
  Последняя строка при включённом хуке — инструкция проверки хука: покажи её дословно, как
  напечатана, не пересказывай и не сокращай.
- **Код 2** — ответ не прошёл проверку, в тексте ошибки имя поля (`people[1].id`, `models.judge.effort`);
  ничего не записано. Задай соответствующий вопрос заново и повтори вызов целиком.
- **Код 1** — данные: например, `~/.claude/settings.json` не разбирается. Перескажи ошибку; запись
  этого файла не обходится.

Затем состояние всех пунктов:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" doctor
```

Объясни строки онбординга: `sources_found` (папки каких источников найдены), `project_agents`
(`3/3 совпадают с config.models` — ок; `расходятся: …` — сверить командой
`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sr.py" agents check`), `gitignore`, `show_scores`,
`period_mode`, `template`, `hook_enabled` и срок хранения логов Claude Code. Совет «агент правлен вручную» —
перезапись `agents write --force` только по явной просьбе пользователя: она сотрёт его правки.

Следующий шаг для пользователя: собрать логи `/sessionretro:collect`, затем ретро `/sessionretro:review`.

## Что скилл вправе писать

Писать можешь ТОЛЬКО через `sr.py`:

- `.sessionretro/` проекта (конфиг, карточки, шаблон) и строка реестра в `~/.sessionretro/` — через `setup-apply`;
- `.claude/agents/sessionretro-*.md` проекта — через `setup-apply` или `agents write`;
- `.gitignore` проекта — через `setup-apply` при `"gitignore": true`;
- `~/.claude/settings.json` — только через `setup-apply` при `cleanup_period_days.write: true` после явного «да».

ЗАПРЕЩЕНО: править эти файлы Write или Edit, ставить программы (SpecStory ставит пользователь),
перезаписывать карточки людей и агентов с правленым телом без просьбы, писать в файлы пользователя
абсолютные пути плагина.

## Предложения движку

Упёрся в ограничение плагина (нужный ответ `setup-apply` не принимает, вариант не ложится в
формат, пришлось обходить руками) — действуй по протоколу `${CLAUDE_PLUGIN_ROOT}/references/improvements-protocol.md`:
сначала обход, потом одна реплика с вопросом и запись `improve add` только по согласию.
