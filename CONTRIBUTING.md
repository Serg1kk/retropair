# Как внести вклад в sessionretro

Спасибо, что хотите помочь. Здесь — как предложить изменение, что обязательно в PR и чего
присылать нельзя. Роли и порядок решений — в [MAINTAINERS.md](MAINTAINERS.md).

## Сначала issue

Для всего, кроме опечаток, начните с issue по одному из шаблонов:

- **Proposal** — улучшение оценки, текста, отчётов или онбординга: что предлагаете, какую
  проблему решает, где в плагине, как понять, что стало лучше;
- **Bug** — ошибка скрипта, скилла или отчёта: шаги, ожидание, текст ошибки
  `sessionretro: …`, версия плагина, ОС и python;
- **Privacy** — в текст, отчёт или лог попали личные данные или секреты: какого рода данные и
  на каком шаге, **без самих данных**.

Вопросы и идеи без готового предложения — в Discussions репозитория на GitHub. Почты нет.

Если плагин сам предложил записать улучшение, файл лежит в
`.sessionretro/improvements/` вашего проекта: перечитайте его и вставьте в issue.

## Чего не присылать

Ни в issue, ни в PR, ни в тестовых данных:

- логи сессий — ни целиком, ни фрагментами, даже «очищенные»;
- имена, хэндлы, e-mail, фото людей, чьи логи вы смотрели, и цитаты из их текстов;
- ключи, токены, внутренние адреса и пути вашей машины (`/home/<вы>/…` и подобные);
- карточки людей и содержимое `.sessionretro/` реальных проектов.

Нужен пример — придумайте его: вымышленное имя (`alex`, `sam`), путь `/home/user/…`,
синтетический лог из трёх-четырёх ходов.

## Как устроен код

```text
scripts/sr.py                 # единая точка входа CLI
scripts/lib/cmd_<команда>.py  # по файлу на команду, подключаются автоматически
scripts/lib/*.py              # конфиг, карточки, workspace, реестр, схемы, блокировка
scripts/tests/                # unittest, фикстуры в tests/fixtures/
references/                   # схемы, строки интерфейса
templates/                    # шаблоны конфига и карточки
skills/, agents/, hooks/      # скиллы, агенты и хук Claude Code
docs/ru/, docs/en/            # документация для пользователя: все страницы на русском, парные — на английском
demo/                         # обезличенный демо-workspace
```

Только python 3.10+ и стандартная библиотека — без сторонних пакетов.

**Новая команда** — это новый файл `scripts/lib/cmd_<команда>.py` (дефис в имени команды
становится `_`) с функцией `register(subparsers)`; `sr.py` править не нужно. Handler
возвращает код выхода: `0` — ок, `1` — данные не сошлись или не прошли проверку, `2` —
неверный вызов. Ожидаемые ошибки — `SrError(message, code)` из `scripts/lib/workspace.py`,
текст в виде `<что упало>: <почему> (<параметры>)`. Тихих фоллбеков нет: если чего-то не
хватает, команда говорит об этом и выходит с кодом, а не подставляет дефолт.
Полный контракт — докстринг `scripts/lib/registry_cmds.py`.

**Состояние** пишется только в `.sessionretro/` проекта и `~/.sessionretro/`, атомарно; в
папку плагина код не пишет никогда. Правила — [STATE.md](STATE.md). Поля `config.json` и
карточки можно только добавлять как необязательные.

## Pull request

1. Форк, ветка от `main`, одна тема на PR.
2. **Тесты обязательны.** Любой новый или изменённый скрипт приходит с тестами в том же PR:
   синтетические данные, по тесту на каждую ветку проверки. Тесты пишут только во временные
   папки и подменяют `HOME` (см. `scripts/tests/_util.py`).
3. Прогон из корня плагина — зелёный:

   ```bash
   PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -v
   claude plugin validate .
   ```

4. Документация: поменялось поведение команды — поправьте страницу в `docs/ru/`. Две пары
   правятся только вместе, в том же PR:
   - правите `README.md` — правите `README.ru.md` (разделы `##` в одном порядке, это проверяет
     тест), и наоборот;
   - правите любую страницу `docs/ru/<имя>.md`, у которой есть пара `docs/en/<имя>.md`, —
     правите пару в том же PR, и наоборот. Страница без пары в `docs/en/` правится одна.

   Относительные ссылки в `*.md` проверяются тестом: они должны вести на файлы внутри плагина.
5. В описании PR: что меняется, зачем, как проверяли (вывод тестов).
6. Правки референсов осей и промптов оценщика — с результатами на golden set до и после
   (см. [MAINTAINERS.md](MAINTAINERS.md)).

Мейнтейнеры дополнительно гоняют гейты чистоты: запрещённые слова и ссылки, e-mail, пути
домашних папок, совпадение версий. Если гейт покраснел на вашем PR, в комментарии будет строка
с файлом и фрагментом.

## Стиль

- Сообщения об ошибках говорят, что упало, почему и с какими параметрами (путь, id, код).
- Документация — для человека: без внутреннего жаргона, с примерами команд, на русском — на
  «вы». Пути к плагину в примерах — через `${CLAUDE_PLUGIN_ROOT}`.
- Лицензия — MIT ([LICENSE](LICENSE)); присылая PR, вы соглашаетесь выпустить вклад под ней.
